# Performance baseline

One row per case that runs: allocations, bytes allocated, peak live bytes,
instructions and code bytes. These are deterministic, measured by the
instrumented build, and every case's run must reproduce its row exactly: a case
whose numbers moved fails with `performance baseline moved`, and a case with no
row fails too. `cargo handoff` rewrites the rows that moved, and lists them for
review; the failure names the scoped refresh that accepts a change by hand.

The metrics that differ from run to run are in `performance_trends.md`.

`AIPL_CASE` (a path substring, or a comma-separated list) rewrites only the
matching rows; rows whose case no longer exists are always dropped.

```
cargo test --test cases -- --ignored refresh_baseline
```
