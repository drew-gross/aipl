# Performance metrics

One row per case that runs. The columns come in two groups.

**Asserted** — allocations, bytes allocated, peak live bytes, instructions and
code bytes. These are deterministic, measured by the instrumented build, and
every case's run must reproduce its row exactly: a case whose numbers moved
fails with `performance baseline moved`, and a case with no row fails too. The
failure names the scoped refresh that accepts the change.

**Not asserted** — wall-clock (measured in-process, so process spawn/teardown is
excluded), build time (load + compile + link) and peak resident memory. These
drift run-to-run, so they're checked in only to track trends.

Regenerate and review the printed summary with the command below. `AIPL_CASE`
(a path substring, or a comma-separated list) rewrites only the matching rows;
rows whose case no longer exists are always dropped.

```
cargo test --test cases -- --ignored refresh_perfmon
```
