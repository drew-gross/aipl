One row per case that runs: wall-clock (measured in-process, so process
spawn/teardown is excluded), build time (load + compile + link) and peak resident
memory. These drift run-to-run, so nothing asserts on them, and nothing but the
refresh below writes this file: it holds the numbers as of the last time someone
chose to look. Run it before and after a change to see its effect, or now and
then to see the trend, and read the printed summary.

The deterministic metrics every case is held to are in `performance_baseline.md`.

`AIPL_CASE` (a path substring, or a comma-separated list) rewrites only the
matching rows; rows whose case no longer exists are always dropped.
