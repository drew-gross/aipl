# str24 burn-down — what the 24-byte `str` switch has not reached yet.
#
# The switch (`STR_REPR.md`, stage 1) is committed but **off**: codegen emits it
# only when `AIPL_STR24` is set. Off, the compiler is byte-for-byte what it was
# and the suite is green; on, you get the new representation and the failures
# below. That gating is what lets the work land in main without a red suite.
#
# This is a ratchet: entries come out as the switch reaches them, and none go in
# to quiet an unrelated failure. When it is empty, stage 1 is done and the
# `aipl_*` half can be deleted.
#
#   cargo build && AIPL_STR24=1 cargo nextest run --no-fail-fast
#
# ---------------------------------------------------------------------------
# Why this is a list and not a set of `#[ignore]`s
#
# Two full runs under the switch failed 39 tests and 13 tests — with **no
# overlap**. The breakage is nondeterministic: a value that is 24 bytes to one
# code path and 8 to another corrupts whatever happens to sit next to it, and
# what that is depends on allocation order. So there is no stable set to ignore,
# and marking tests `#[ignore]` would have suppressed a moving target. Gating the
# switch off by default is the honest way to keep the suite green; this file is
# then a record of the work, not a suppression mechanism.
#
# ---------------------------------------------------------------------------
# Current state of the switched path (`AIPL_STR24=1`)
#
# Working end to end:
#     fn main() -> i64 { 7 }                 -> 7
#     print("short")                         -> short          (inline literal)
#     print("hello from a twenty-four ...")  -> hello ...      (static buffer)
#
# Not yet: anything calling a `str` builtin other than `print` — `len` on a
# literal returns garbage, because `active_sym` only remaps the entry points
# whose call sites have been converted and verified.
#
# ---------------------------------------------------------------------------
# Known-failing clusters, measured when literals and print were working. Counts
# are from that run; treat them as the shape of the work, not a current tally.
#
# 11  The FFI read path, **partly done**. The readers now take the callee's
#     `StrAbi` and read a wide `str` as the 24 bytes at the slot; that retired
#     five of the original sixteen (optional returns, array validation, the
#     grow-into-a-copy case, the doc example). What is left crashes rather than
#     mismatching, so the remaining cause is structural — composite *returns*
#     carrying a `str`, where the sret buffer and the field offsets have to agree
#     with a layout the callee computed under the wide representation.
#
#     **Diagnosed by experiment — the FFI is not the problem.** Two throwaway
#     tests settled it:
#
#       `pub fn id(s: str) -> str { s }` through `call_values`  ->  PASSES,
#           for an inline arg *and* a buffer-backed one. So the read path,
#           argument marshaling and cross-boundary refcounting are all correct.
#
#       the same shape whose body calls one string builtin (`+++`)  ->  SIGSEGV.
#
#     So these 11 fail because their fixtures *use string builtins*, whose call
#     sites still route to the old entry points with what is now an address.
#     Two hypotheses died here and are not worth retrying: the return convention
#     (a wide `str` return does go through sret now — that fix is in, and changed
#     nothing) and cross-boundary ownership (nothing is double-released; the
#     identity round trip proves it).
#
#     The work is therefore *not* in the FFI: it is converting the `str` builtin
#     call sites one at a time. `aipl_concat` was tried as a straight `active_sym`
#     rename and still crashes, so it needs more than a symbol swap — start
#     there, and note `aipl_concat` also appears in the concat-specialization
#     machinery, which is the likely reason.

# The builtin conversion inventory
#
# 34 runtime symbols take or return a `str`. Six are done (print, print_error,
# inc, dec — the last two named at the `emit_rc_w` site rather than remapped).
# The rest split by whether their `aipl2_*` entry point already exists.
#
# **Prefer porting to AIPL over writing an `aipl2_*` entry point.** A builtin
# written in AIPL compiles to whichever representation is active, so it leaves
# this list entirely rather than moving down it — and it serves the self-hosting
# goal at the same time. `is_all_whitespace` went that way and is gone from the
# inventory: it is now `self.all(is_whitespace)` in
# `aipl-mono/src/builtin_is_all_whitespace.aipl`, its native implementation is
# deleted from both runtimes, and the artifacts no longer reference the symbol.
#
# The bar is performance. That port cost ~13x on a micro-benchmark and roughly
# doubled the small whitespace-only files (`dedent` 6,490 -> 14,274 instructions)
# because `all` dispatches a lambda per char where the native loop scanned
# chunks — but the workloads that dominate real compile time barely moved
# (`lex_aipl` +0.02%, `doc` +1.6%), which is what made it acceptable. Measure the
# aggregate, not the micro-benchmark, and check the same numbers before porting
# the next one.
#
# It also needed a new intrinsic: `is_space` covers four characters, ASCII
# whitespace has six, and AIPL has no numeric escape for the other two — so
# `is_whitespace` exists as a compiler intrinsic to keep the port faithful rather
# than silently narrowing. Expect that shape of blocker again: a port is only
# honest if the language can express what the native version did.
#
# A. Entry point EXISTS — convert the call site and verify (17). Cheapest first:
#    the pure query ones have no ownership to get wrong.
#
#      queries      str_len, str_eq, str_cmp, str_hash, char_at, starts_with,
#                   starts_with_at, ends_with, contains, str_data
#      producers    str_slice, concat, trim, str_reverse, str_sort, str_repeat
#      iteration    str_iter_init  (with str_iter_next, already Word-typed)
#
#    `concat` was tried as a plain rename and still crashes: it also appears in
#    the concat-specialization machinery (`$c{i}` instances, `ConcatStr`), so it
#    is not the one to start with despite being the obvious target.
#
# B. Entry point MISSING — write it, then convert (13):
#
#      containers   str_split, str_join, arr_join
#      concat kin   concat_lazy (the `+` rope path), concat_mut
#      mutation     trim_mut
#      files/proc   read_file_to_string, write_string_to_file, list_files,
#                   execute_program
#      test runner  assert, test_begin, test_fail
#
# Beyond these 35, two pieces of work carry no `Str`-typed symbol of their own
# and so do not appear above:
#
#   - `emit_render` (the `to_str` builder). It drives `str_alloc` and the
#     `write_*` cursors, which are `Word`-typed because they traffic in raw
#     pointers. The `aipl2_str_alloc`/`str_write_ptr`/`str_grew` trio replaces
#     that idiom; the rewrite is in `emit_render`, not in a symbol swap.
#   - Element helpers for containers holding a `str` — arrays, sets, dicts.
#     `aipl2_arr_drop_str`/`aipl2_arr_retain_str` are the first two; each
#     container path needs its 24-byte counterpart.
#
# Suggested order: the eleven queries first (no ownership, immediate signal from
# the corpus), then iteration, then the producers, then `emit_render`, then the
# containers — leaving concat and the file/test-runner ops last, since they are
# entangled with specialization and with `aipl check` respectively.
