# str24 burn-down — CLOSED.
#
# The 24-byte `str` is the only representation: the switch is gone, the tagged
# half is deleted, and the artifacts were regenerated against the one ABI. What
# follows is the record of how it was done, kept because the *shapes* recur —
# every future representation change will meet them again.
#
# Final state: 932 / 932 pass, no env var, no second runtime.
#
# ---------------------------------------------------------------------------
# What the flip itself cost, in order
#
#   1. **Default to wide.** One function returning `true`. The compiler kept
#      working immediately, because the dual ABI let it emit wide code while
#      still calling its dogfooded engines through their tagged artifacts — the
#      whole reason the two ABIs coexisted.
#   2. **Regenerate the artifacts.** `cargo handoff` did the staged-IR flow on
#      its own: 504 sections refilled, IR promoted.
#   3. **Delete the switch.** 37 `str24_enabled()` branches collapsed to their
#      wide arm. Emitted code unchanged, so the gate needed *no* regeneration —
#      which is what proved the deletion was inert.
#   4. **Delete the tagged runtime**, both halves, and every helper the compiler
#      could then see was dead: `StrRepr`, `str_bytes`, `pack_inline`,
#      `concat_materialize`, the tagged iterator, the tagged SSO `to_str`, the
#      tagged file/spawn/walk paths. ~7,000 lines gone.
#   5. **Take back the names.** `aipl2_*` → `aipl_*`, and `active_sym` — the
#      remap that existed only while both name sets did — disappeared with it.
#
# Two things fell out that were worth more than the deletion:
#
#   - **`Args` collapsed to one case.** Every entry point borrows its arguments
#     now, so "does this builtin consume what it is handed?" stopped being a
#     question with two answers. The old convention existed because a tagged
#     `str` was a bare pointer whose lifetime had to be managed across the call;
#     a 24-byte value is passed by address to something the caller is already
#     keeping alive. `borrowed_param` is the statement of the protocol.
#   - **`ArgKind` collapsed too.** Naming argument kinds (`Word` vs `Str`) was
#     scaffolding for exactly this flip; afterwards every argument is one word
#     and the table is back to counting them — the same shape the artifact
#     manifest's table already had, so the two now agree in form as well as
#     content.
#
# ---------------------------------------------------------------------------
# The one real bug the flip exposed
#
# `aipl_arr_join` was labelled `Ret::Str`. It returns a `T[]`, not a `str` — but
# while every result came back in one register, `Ret::Str` and `Ret::Word` were
# indistinguishable and the mislabel was invisible. The moment `Ret::Str` came to
# mean "written through a leading out pointer", codegen started prepending a
# buffer for a value that comes back in a register, and `arr_join` corrupted its
# parts list.
#
# **That is the shape to expect from any representation change: not the code that
# knew about the representation, but the code that had been wrong all along in a
# way the old uniformity hid.** Four of these turned up over the migration —
# `field_size` duplicating `elem_size_of`, `dict_key_size` hardcoded to 8, a
# `str!Error` payload sized from the ok side, and this. Each was a rule computed
# twice, or from one representative, and each agreed with itself only while
# everything was one word.
#
# ---------------------------------------------------------------------------
# Why this is a list and not a set of `#[ignore]`s
#
# Two full runs under the switch failed 39 tests and 13 tests — with **no
# overlap**. The breakage is nondeterministic: a value that is 24 bytes to one
# code path and 8 to another corrupts whatever happens to sit next to it, and
# what that is depends on allocation order. So there is no stable set to ignore,
# and marking tests `#[ignore]` would have suppressed a moving target. Gating the
# switch off by default is the honest way to keep the suite green; this file is
# then a record of the work, not a suppression mechanism.
#
# ---------------------------------------------------------------------------
# Current state of the switched path (`AIPL_STR24=1`)
#
# Working end to end:
#     fn main() -> i64 { 7 }                 -> 7
#     print("short")                         -> short          (inline literal)
#     print("hello from a twenty-four ...")  -> hello ...      (static buffer)
#
# Also working: the whole observer surface — `==`, `<`, `>`, `len`, `hash`,
# `contains`, `starts_with`, `ends_with`, `char_at` — verified together in one
# program under both settings.
#
# **Producers, not consumers, are the remaining work.** Values were still being
# *built* by the old representation while consumers read them as 24 bytes. The
# sharpest case was `char[]` — str-shaped (`is_char_array`), so a composite under
# the flag, but its literal packed content into the 8-byte value:
#
#     ['c', 'a', 'b'] . len()   ->  misaligned pointer dereference at 0x62615b,
#                                   which is the bytes `[`, `a`, `b`
#
# Read as a 24-byte value, the content *was* the pointer, so `len` returned
# garbage and a fold over `0..len` ran ~forever. That is why
# `cases_arrays_min_max` — a case with no strings in it at all — *hung* rather
# than failed. **Fixed**: the literal now builds through
# `aipl2_str_alloc`/`str_write_ptr`/`str_grew`, since the new value points at its
# buffer rather than being it, and allocation gives capacity rather than length.
#
# Still to convert: `str` literals inside composites, and the concat family.
#
# ---------------------------------------------------------------------------
# **Counting flag-on failures was measuring the wrong thing.**
#
# The count went 39 -> 523 -> 527 across the conversions, which reads like no
# progress at all. Classifying a run rather than counting it showed why: 180 of
# the 527 were `--- performance ---` mismatches, which are **expected and
# uninformative**. Allocations, executed instructions and binary size all change
# when the representation changes, and nearly every case asserts them, so a
# perfectly correct switch still fails all 180 — burying the failures that do
# carry information under a bucket that can only empty on the final flip.
#
# So the harness now **skips `--- performance ---` entirely under `AIPL_STR24`**
# (`perf_sections_apply` in `tests/cases.rs`), which also gates *filling*: a
# `fill_expected` run with the variable set would otherwise write wide numbers
# into a corpus the default build then fails against. The sections are refilled
# once, at the flip.
#
# **The leak gate is *not* skipped**, and needs no second env var. The section
# splits cleanly in two: `allocations == deallocations` is an invariant, while
# bytes allocated / instructions executed / binary size / the `functions:` block
# are measurements that legitimately move. So the section is still measured and
# the leak gate still runs on every flag-on case; only the comparison against
# the expected body is skipped (`str24_mode` in `tests/cases.rs`).
#
# That matters more than it sounds: the leak gate is the migration's only
# tripwire for a mis-declared ownership protocol, which changes neither output
# nor exit code. Verified by reintroducing the `print` leak below — **117 cases
# fail with `memory leak`**, and zero do with it fixed.
#
# ---------------------------------------------------------------------------
# **Ownership follows the remap, automatically** (`args_for`)
#
# `SIG_REGS` records what each *tagged* native implementation does to its heap
# arguments, because that is the only thing readable off the source. But every
# `aipl2_*` entry point borrows — so the moment a symbol is remapped, its table
# entry describes an implementation that is no longer being called. `args_for`
# closes that gap by keying off `active_sym`: a remapped symbol is `Borrows`
# whatever the table says.
#
# This was already biting. `__builtin_print` is `Args::Consumes`, so the caller
# retained and `aipl2_print` — which borrows — never released: a leak on every
# `print` under the flag, invisible because it neither crashes nor changes
# output, and unmeasured because the perf skip had just retired the assertion
# that would have caught it. Deriving the answer rather than maintaining a second
# table means the next conversion cannot reintroduce it.
#
# Ten clusters were fixed on the strength of that classification, and the count
# is now **0 / 932**, with zero leaks (from 527 of 875 — the denominator grew when the gate
# started running the workspace's unit tests too, see CLAUDE.md):
#
#   - **link failed: 186 -> 0. The AOT runtime had no wide I/O.** `aipl2_print`
#     and `aipl2_print_error` lived only in `str24_host.rs`, which is std-only
#     and is *not* included in the no_std linker runtime — only `str24.rs` is. So
#     every program that printed anything compiled and then failed to link
#     (`Undefined symbols: "_aipl2_print"`), while one that printed nothing built
#     fine. Fixed by writing the AOT counterparts in `aipl_runtime.rs` on top of
#     `str24::for_each_chunk` and `libc::write`, mirroring `aipl_print` — except
#     that they do **not** release their argument, since an `aipl2_*` entry point
#     borrows.
#
#     Worth remembering as a shape: the shared-layout / split-I/O arrangement
#     means a new entry point is only half-written until *both* runtimes have it,
#     and the JIT half passing tells you nothing about the other.
#
#   - `fmt::` and `highlighting::` (7 tests) went green as a side effect — they
#     were downstream of the print path.
#
#   - **the test-runner builtins.** `assert`, `test_begin` and `test_fail` now
#     have `aipl2_*` entry points in both runtimes, and all 19 `check::` tests
#     pass under the flag; a failing assert, a `?` on an `err` and a `?` on a
#     `none` all report byte-identically either way.
#
#     One design point: `aipl_test_begin` stores its argument *pointer* in a
#     global and reads it back at report time. A wide `str` argument points at
#     the caller's 24-byte stack slot, and outliving the call is exactly what a
#     stack slot does not promise — so `aipl2_test_begin` materializes the name's
#     text instead (`TEST_CUR_NAME_WIDE`). Expect that wherever an entry point
#     keeps an argument past its own return.
#
#     **It did not account for the 90, and the earlier attribution was wrong.**
#     Only the 6 `check::` suite tests were caused by these builtins. The
#     case-level "`aipl check` failed" bucket is 92 both before and after, and
#     sampling it shows the real cause: `min("x" +++ "yz", ...)` aborts in
#     `aipl2_str_cmp` on a *tagged rope* — `concat` is an unconverted producer,
#     so a converted reader meets a value the old representation built. The
#     lesson is the one this file keeps re-learning: attribute a cluster by
#     reading one failure, not by matching its shape to a plausible cause.
#
#   - **the concat family** — see the producers section below. `+++`, its
#     in-place `set s = s +++ r` form, template interpolation and rope
#     lexicographic compare all produce byte-identical output under both
#     settings, and the corpus-wide allocation balance is clean.
#
#   - **arrays holding a `str`** — see the element-helper note below. Plain
#     `str[]` and nested `char[]` build, iterate, index, render and free
#     identically under both settings.
#
#   - **sets and dicts holding a `str`** — as key, as value, and as set element,
#     verified identical under both settings and in an AOT binary as well as the
#     JIT. Three things came out of it, all bigger than the cluster:
#
#     **`str_cmp` now carries a width, not a flag.** The set/dict helpers all
#     took a 0/1 `str_cmp`, which was enough while every `str` was one word. It
#     no longer is — they need to know both how to compare *and* how wide the
#     thing is, since a set strides over elements and a dict's value sits
#     immediately after its key. Carrying the width (`str_cmp_width`) answers
#     both with the argument that was already there, and needs no new symbol in
#     either runtime — which matters because the AOT half has no env var to
#     consult.
#
#     **The dict pair layout is now derived** (`dict_key_size`/`dict_pair_size`).
#     `8` was hard-coded at eight sites that build, scan, hash, render, free and
#     look up pairs; they cannot disagree now. A disagreement reads a key's bytes
#     as a value's — which is how a wide `str` key first surfaced, as
#     `misaligned pointer dereference: ... is 0x63`, the letter `c`.
#
#     **A latent bug in the *tagged* path, exposed by the switch.** Five sites
#     retained an array or set through `emit_inc`, i.e. `aipl_inc` — whose own
#     doc says arrays must use `aipl_arr_inc` because `aipl_inc` dispatches on
#     the *string* tag scheme. It survived only because the two coincide for an
#     untagged array (both find the refcount at `ptr - 8`); a tagged array
#     representation would have misread it either way. Now fixed for both ABIs.
#
#     Three call sites also spilled a queried key/element into a fixed 8-byte
#     slot (`has`, `get`, `contains_key`). They use `value_slot` +
#     `store_array_elem` now, which size and write by type — otherwise a
#     composite's *address* is stored where the runtime reads a value.
#
#   - **structs, variants, optionals and results holding a `str`** — the whole
#     composite-layout cluster, and it came down to **one duplicated rule**.
#
#     `field_size` had its own `match` for "how many bytes does this occupy",
#     alongside `elem_size_of`'s. They agreed by coincidence while every `str`
#     was one word; they stopped agreeing the moment one wasn't, because the
#     duplicate's catch-all said 8 — so every `str` field overlapped the field
#     after it. A struct field, a variant payload slot and an array element are
#     the same question asked three times, so `field_size` now just calls
#     `elem_size_of`. That deletion alone fixed structs, variants, results and
#     five of the eight `ffi::call_values_*` tests.
#
#     Separately, `str?[]` needed genuinely new element helpers
#     (`aipl2_arr_drop_opt_str` / `aipl2_arr_retain_opt_str`): a flattened
#     optional is `{tag, value}`, so the wide stride is a word plus a whole
#     `Str`, and the value is released *in place* where the tagged version read a
#     pointer. The wide form also cannot share one retain helper with `T[]?[]`
#     the way the tagged one does — an array element is still 8 bytes, so only
#     the `str?` case changes shape.
#
#   - **the producers**: slice, trim, reverse, sort, repeat, split and join.
#     All `compile failed` went to zero with them — an unconverted producer had
#     been failing cranelift's verifier (`mismatched argument count ... got 2,
#     expected 1`), because a `str`-returning builtin is composite under the flag
#     so the generic call path prepends an sret pointer the tagged symbol has no
#     parameter for. A good failure mode, and it retires itself on conversion.
#
#     Two things worth carrying forward:
#
#     **A producer that returns a *window* must retain inside the entry point.**
#     `slice` and `trim` share the input's owner rather than copying — the whole
#     point of the representation — and the internal `Str::slice` is the
#     ownership-transferring form that takes no reference. Since an `aipl2_*`
#     entry point only borrows, the retain belongs at the boundary.
#     `reverse`/`sort`/`repeat` allocate fresh and need nothing.
#
#     **`split`/`join` are split across the two runtimes on purpose.** They build
#     and read *arrays*, and the array runtime is per-runtime — but where the
#     cuts fall and how parts are streamed back together is exactly what would
#     diverge silently, so that lives in `str24.rs` (`for_each_split`,
#     `join_from`) and each runtime keeps only the handful of lines that allocate
#     an array and address its elements. `for_each_split` is callback-driven
#     rather than returning a list precisely so it needs no allocation: the same
#     code serves the counting pass, the filling pass, and the `no_std` runtime
#     that has no `Vec`.
#
#   - **the `char[]` append path** (`push`, `extend`) and, with it, `mut`
#     bindings generally. Four bugs, three of them the same one:
#
#     **A wide handle is not a snapshot.** A tagged `str` read out of a slot is a
#     copy of a *pointer*, so it kept naming the old buffer however the slot
#     changed afterwards — value semantics for free. A wide handle is the slot's
#     address, so it names whatever is there *now*. Three places relied on that
#     accident: `set s = <str>` and both append paths released the old value
#     *after* storing the new one (freeing what was just assigned), and
#     `let snap = cs` aliased the slot outright, so a later `push` mutated the
#     snapshot. Releases now happen before the store, and reading a `mut` binding
#     copies the 24 bytes (`copy_str_value`) — which is exactly what the tagged
#     pointer-read gave for nothing.
#
#     The fourth: a `mut` binding's slot was a fixed 8 bytes, its comment
#     claiming that "fits any i64/bool/char/str". Only the wide `str` widens —
#     broadening it to every composite silently switched struct bindings from
#     pointer-holding to value-holding, which the leak gate caught.
#
#     Note the release-before-store reorder applies to **both** ABIs. It is
#     equivalent and green, but it did change committed-path codegen (the perf
#     refills and IR regen of that turn); gate it on `str24_enabled()` if the
#     tagged path should stay byte-identical.
#
#   - **the file entry points**: `read_file_to_string`, `write_string_to_file`,
#     `list_files`, in both runtimes, verified JIT and AOT.
#
#     **A null return cannot signal failure any more.** The tagged entry points
#     returned a null `str` on error and codegen tested it. A wide `str` result
#     travels through an out pointer the *caller* allocates, so there is no null
#     to return: `aipl2_read_file_to_string` takes the out pointer and returns
#     1/0 instead. Better anyway — "did it work" and "what did it produce" stop
#     sharing one channel.
#
#     And a second layout rule that had been true by coincidence: the `str!Error`
#     payload region is sized to the *wider* side. For `str[]!Error` the ok side
#     is an 8-byte array pointer while the err side is now a 24-byte `str`, so
#     sizing from the ok side put the message past the end of the slot.
#
#     The AOT half needs NUL-terminated paths, and a wide `str` is a *window*
#     that carries no terminator — slicing being free is the point — so
#     `c_path_of` makes one. It allocates rather than using a fixed stack buffer,
#     so there is no path-length ceiling.
#
#   - **the two `char[]` push/extend leaks**, and they were one line.
#
#     `is_composite` answers *true* for a wide `str`/`char[]` — they travel by
#     address like any other composite — so a non-exclusive `mut char[]` binding
#     started falling into `LetMut`'s **composite** arm, which gives the slot its
#     own reference. That is exactly the ownership model `char[]` is excluded
#     from one branch earlier: `mut_binding_owns_slot_ref` spells out
#     `Array(_) && !is_char_array(ty)`, because the `push` path assumes the slot
#     holds no reference of its own. So the slot retained the *old* value and
#     then released whatever the slot held at exit — the value `push` had
#     replaced it with. The old value leaked, the new one was released twice, and
#     the two errors cancelled in the tally, which is why it read as a plain
#     off-by-one. Fixed by guarding that arm with `!is_str_shaped`.
#
#     **Generalize this one.** `is_composite` gained `|| str24_wide(ty)` early in
#     Stage 1 so address-passing worked everywhere. Every *other* consumer of
#     that predicate then silently started including `str`, and most of them
#     wanted that. This is the one that did not — and the tell was already in the
#     tree, in a sibling branch that had bothered to exclude `char[]` by name.
#     When a wide `str` behaves oddly in code that asks `is_composite`, check
#     whether the neighbouring branches exclude `char[]`.
#
#     Found by bisecting the case body down to
#     `mut cs = ['a']; let snap = cs; set cs.push('b');` — the snapshot is what
#     makes the binding non-exclusive — and then logging every `aipl2_inc`/`dec`
#     with its owner, length and refcount. The trace named the bug outright: one
#     buffer inc'd once and dec'd once, another dec'd twice.
#
#   - **the FFI composite-array marshalling**, which was `char[]` three times.
#
#     `char[]` shares `str`'s representation, so under this ABI it is composite —
#     `abi_is_composite` says so, keying on `is_str_repr(ty) || is_char_array(ty)`.
#     Three sites in the marshalling layer had been written when only a real
#     `str` could be composite, and each asked `is_str_repr` alone:
#
#       - `write_ffi_arg` fell through to `ffi_arg_word`, whose own
#         `debug_assert!` catches exactly that ("a composite goes through
#         `ffi_arg_abi`") — the assertion was right and the caller was wrong.
#       - `read_ffi_borrowed`'s `Array` arm read an 8-byte word where a 24-byte
#         value sits, so it decoded the value's first field: an empty array.
#       - the *return* path chose sret on `ret_is_str`, so a `char[]` return came
#         back through the word return with the same empty-array result.
#
#     All three are now `is_str_shaped`, differing only in how the host spells
#     the value: a `str` is text, a `char[]` is codepoints (`chars_to_utf8` and
#     its inverse). **Whenever a wide `str` misbehaves, grep the neighbourhood for
#     `is_str_repr` and ask whether it meant `is_str_shaped`** — that is now the
#     fourth cluster with this shape, after the `is_composite` leak.
#
#   - **`execute_program`, the CLI argument array, `sort`, `contains` with a
#     `char` needle, `starts_with_at` past the end, and the in-place `filter`.**
#     Done as one batch; `arr_join` and `int_parse` turned out to need nothing —
#     they never appeared in a failure once their neighbours were converted.
#
#     **The AOT runtime can now ask which representation it is linked against.**
#     It is a `no_std` staticlib with no environment, built once and linked into
#     objects of either kind, so it cannot read `AIPL_STR24` the way the JIT
#     does. The *object* now exports a 1-byte flag (`STR24_SYMBOL`,
#     `__aipl_str24`) exactly as it already exported whether `main` wanted its
#     arguments. Needed wherever the runtime builds or walks values on compiled
#     code's behalf with no type to consult — `build_cli_args` is the first, and
#     the pattern is there for the next.
#
#     Two more sites that had been sizing by word:
#       - `aipl_arr_sort` sorted elements *as `i64`s*, which for a wide `str`
#         reorders thirds of values and compares their first fields. The wide
#         comparison lives in `str24::sort_values` so both runtimes share it.
#       - `__filter_keep` / `__map_set` hardcoded a stride of 8, on an in-place
#         gate that (per its own comment) assumed elements are never composite.
#         Both now take the stride and the store from the element type.
#
#     And one semantic difference, not a layout one: `str24::starts_with_at`
#     *rejected* an offset past the end where the tagged runtime **clamps** it,
#     so `"hello".starts_with_at("", 99)` was false instead of true. Worth
#     remembering that the wide implementations are a reimplementation, not a
#     port — they can disagree about behaviour, not just about bytes.
#
#   - **the element-writing paths**: dict equality and hashing, array spread,
#     and the in-place `map` / `filter_map` / `zip_with`. Four distinct causes,
#     three of which are shapes this file has already named once:
#
#       - **A dict pair's value offset** was still the literal 8 in the equality
#         and hash loops (`dict_key_size` covers the rest).
#       - **`is_composite` again.** The `set` arm had the same trap `LetMut` did:
#         a wide `char[]` fell into the composite branch and had its old value
#         released as if the slot held a pointer. Same `!is_str_shaped` guard.
#       - **A reused buffer's slots must fit what is written into them.** The
#         in-place gates live in monomorphization and assumed every reusable
#         element is one word, so `[1, 2].map(to_str)` reused an `i64[]` buffer
#         for `str` results — three words written into each one-word slot. Mono
#         now asks `slot_fits`, which is the one place it has to know the
#         representation; it reads the same env var, with a pointer to codegen's
#         `str24_enabled` as the authority, and goes away at the flip.
#       - **An array element read is a snapshot too.** This is the third face of
#         "a wide handle is not a snapshot", after `set` and `let snap = cs`.
#         `load_array_elem` returned the element's *address*, and the in-place
#         bodies overwrite the very slot they are reading — so the loop's
#         end-of-iteration release hit the value `__map_set` had just written and
#         freed it out from under the array. Reads of a wide element now copy,
#         exactly as a tagged read copied the word.
#
#     `__map_set` also had to release the old value *before* writing the slot,
#     the same reordering `set` and the append paths needed.
#
#   - **the tail-call cycle, and it was a real design consequence, not a bug.**
#
#     `tail_safe_param` excludes composite parameters because `return_call` hands
#     the caller's frame to the callee, so an argument that *points into* that
#     frame dangles at the transfer. A wide `str` is composite, so every
#     `str`-taking function silently lost tail-call elimination — a trampolined
#     mutual cycle became real recursion and overflowed the 8 MB stack of an
#     `aipl build` binary at ~50k deep. The JIT, on a bigger stack, still passed,
#     which is why this presented as the first JIT/AOT disagreement since the
#     `str24.rs` split. Confirmed by swapping the `str` parameter for an `i64`:
#     same cycle, same depth, no crash.
#
#     A wide `str` has a way out the other composites do not — it is 24 bytes of
#     value with its content on the heap — so the `$tail` signature now passes it
#     **by value**, three words in registers, which is what `abi_spike::q1`
#     measured as workable before any of this was written. Only the `$tail`
#     signature changes; the exported trampoline keeps the one-pointer host
#     shape, so the FFI, artifacts and function values are untouched.
#
#     The catch worth remembering: **every** call to a participant targets its
#     `$tail` body, not just the tail ones (the trampoline exists for the FFI),
#     so the split belongs at the argument list, once — not at the `return_call`.
#     Putting it there produced a clean verifier error rather than corruption.
#
#   - **the artifact round trip**, which was one hardcoded assumption.
#     `from_artifact` set `str_abi: StrAbi::Tagged` with the comment "compiled
#     before the switch" — true of the checked-in `.clif`, false of an artifact
#     generated *under* the switch, whose 24-byte values were then read as 8-byte
#     pointers. An artifact now **declares** its representation with a `; str24`
#     manifest marker, and absent means tagged — so every pre-switch artifact
#     keeps its meaning without being touched. Same shape as the `__aipl_str24`
#     object flag the AOT runtime reads: the producer states it, the consumer
#     stops guessing.
#
# ---------------------------------------------------------------------------
# **The burn-down is empty: 932 / 932 pass under `AIPL_STR24=1`, zero leaks.**
#
# What that does *not* mean:
#
#   - `--- performance ---` is still only leak-checked under the flag. The
#     counts change with the representation and are refilled once, at the flip.
#   - The `aipl2_*` entry points do not call `count_builtin!`, so the
#     `functions:` blocks will under-report builtin calls until they do (below).
#   - Stage 1 ends by regenerating the artifacts against `aipl2_*` and deleting
#     the `aipl_*` half. Until then both ABIs are live and the switch is off by
#     default.
#   - `emit_str_iter_next` still takes a call per byte on the wide path (its
#     inlined fast path reads the tagged cursor's layout), and `to_str` allocates
#     a buffer for short results rather than packing them inline. Both are
#     performance debt the flip should collect.
#
# One thing the perf skip defers rather than solves: **the `aipl2_*` entry points
# do not participate in builtin call counting.** `aipl_print` calls
# `count_builtin!`; `aipl2_print` does not, and neither does anything in
# `str24.rs`. Every `functions:` block would therefore under-report builtin calls
# at the flip. Adding the counters is part of the refill step, not a separate
# bug.
#
# ---------------------------------------------------------------------------
# `emit_render` (the `to_str` builder) — DONE
#
# Verified by rendering one fixture under both settings and diffing: `str`
# (inline and past the 22-byte cap), `char`, signed and unsigned ints, `bool`,
# arrays, nested arrays, `char[]`, sets, dicts, optionals, results, structs,
# variants, and a boxed recursive variant. Byte-identical output, exit 0 both
# ways. The composite arms carry the caveat below — they render correctly, but
# only for element types that are not themselves `str`.
#
# Four things this turned up, all of which generalize past `to_str`:
#
#   - **A `str` value is not a byte pointer, and a literal is not a `str`
#     value.** These need *different* helpers, and collapsing them breaks the
#     other ABI. `str_bytes_ptr` always calls `aipl_str_data`, because neither
#     representation stores a contiguous pointer for every case — a tagged value
#     may be inline or a rope, a wide one may be inline. `emit_str_literal`, by
#     contrast, hands back the content pointer directly under both, so its
#     callers take it as-is. Routing literals through `str_bytes_ptr` "for
#     safety" made the wide path abort on a garbage tag; making it identity
#     under `Tagged` made the *unswitched* path bus-error on an inline value.
#
#   - **`aipl_str_data` is now remapped in `active_sym`**, which converts every
#     copying path at once, because they all go through `str_bytes_ptr`. The one
#     thing that differs between the ABIs is the spill scratch: 8 bytes tagged,
#     `INLINE_CAP` (22) wide. That is why the helper owns the slot and no call
#     site opens its own — a slot sized for the wrong ABI is a stack overwrite,
#     silent under test.
#
#   - **An inlined fast path is a layout dependency.** `emit_str_iter_next`
#     open-codes the cursor's fields (`ITER_POS`, `ITER_LEAF_PTR`, ...). The wide
#     `Iter` is a different struct — two whole `Str` values plus two positions —
#     and a wide leaf may be *inline*, so there is no `leaf_ptr` to load at all;
#     the bytes are in the cursor's own words. This is not a matter of
#     substituting offsets, so the wide path takes the runtime call per byte for
#     now. That is a real regression on the switched path only (the call per byte
#     is what the fast path was added to remove, and `for (let c : s)` is what
#     the dogfooded lexer does for a living) and is worth reclaiming once the
#     switch is the only path. Symptom when it was wrong: iteration yielded one
#     byte and then segfaulted, and `char[]` rendered as `[]`.
#
#   - **Where rendering stops and layout begins.** A struct holding a `str` still
#     fails — but so does `let p = P { name: "ada", n: 7 }; print(p.name)`, with
#     no `to_str` anywhere. The layout still reserves 8 bytes for that field, so
#     the field read hands back the first word of a 24-byte value. `emit_render`
#     is representation-correct already (`component` and `is_composite` both know
#     about the wide `str`); what is missing is the layout. Struct, variant,
#     optional and result payloads carrying a `str` are therefore one cluster,
#     and it is the next one.
#

# The builtin conversion inventory
#
# 34 runtime symbols take or return a `str`. Six are done (print, print_error,
# inc, dec — the last two named at the `emit_rc_w` site rather than remapped).
# `print`/`print_error` count as done only since the AOT halves were written; a
# JIT-only entry point still fails every `aipl build`.
# The rest split by whether their `aipl2_*` entry point already exists.
#
# **Prefer porting to AIPL over writing an `aipl2_*` entry point.** A builtin
# written in AIPL compiles to whichever representation is active, so it leaves
# this list entirely rather than moving down it — and it serves the self-hosting
# goal at the same time. `is_all_whitespace` went that way and is gone from the
# inventory: it is now `self.all(is_whitespace)` in
# `aipl-mono/src/builtin_is_all_whitespace.aipl`, its native implementation is
# deleted from both runtimes, and the artifacts no longer reference the symbol.
#
# The bar is performance. That port cost ~13x on a micro-benchmark and roughly
# doubled the small whitespace-only files (`dedent` 6,490 -> 14,274 instructions)
# because `all` dispatches a lambda per char where the native loop scanned
# chunks — but the workloads that dominate real compile time barely moved
# (`lex_aipl` +0.02%, `doc` +1.6%), which is what made it acceptable. Measure the
# aggregate, not the micro-benchmark, and check the same numbers before porting
# the next one.
#
# It also needed a new intrinsic: `is_space` covers four characters, ASCII
# whitespace has six, and AIPL has no numeric escape for the other two — so
# `is_whitespace` exists as a compiler intrinsic to keep the port faithful rather
# than silently narrowing. Expect that shape of blocker again: a port is only
# honest if the language can express what the native version did.
#
# A. Entry point EXISTS — convert the call site and verify. The queries and
#    iteration are done; what is left are the producers.
#
#      producers    DONE — str_slice, concat, trim, str_reverse, str_sort,
#                   str_repeat, and (group B, written for this) str_split,
#                   str_join
#
#    Converted: str_len, str_eq, str_cmp, str_hash, char_at, starts_with,
#    starts_with_at, ends_with, contains, str_data, str_iter_init/_next.
#
#    **The concat family is DONE.** All three tagged spellings — `aipl_concat`'s
#    eager copy, `aipl_concat_lazy`, and `aipl_concat_mut`'s in-place append —
#    collapse to the single `aipl2_concat`, because building a rope is O(1) and
#    leaves the other two nothing to optimize over the lazy form.
#
#    The `ConcatStr` / `$c{i}` machinery turned out **not** to be in the way, and
#    the earlier note here saying otherwise was wrong. `ConcatStr` is a mono-only
#    pseudo-type that picks a specialized *instance*; codegen treats it as a
#    plain `str` via `is_str_repr`. Nothing about it is representation-specific.
#    The reason the plain rename failed was ownership, not specialization.
#
#    Two entry-point bugs found by writing the *artifact* symbol table, both
#    latent and neither reachable from a JIT run alone:
#      - `aipl2_str_starts_with_at` was registered with the JIT and remapped in
#        `active_sym` but had **no `import_abi` arm**, so any program calling
#        `starts_with_at` panicked the compiler with "unknown builtin import
#        symbol". A remap has *four* parts, not three: `active_sym`, the call
#        site, JIT registration, and `import_abi`.
#      - `aipl-artifact` keeps its own hand-maintained copy of that table and
#        knew no `aipl2_*` symbol at all, so no artifact could carry one.
#        Now filled in.
#
# B. Entry point MISSING — write it, then convert (13):
#
#      containers   str_split, str_join, arr_join
#      concat kin   concat_lazy (the `+` rope path), concat_mut
#      mutation     trim_mut
#      files/proc   DONE — read_file_to_string, write_string_to_file,
#                   list_files. Still open: execute_program.
#      test runner  assert, test_begin, test_fail   <- DONE (both runtimes)
#
# Beyond these 35, two pieces of work carry no `Str`-typed symbol of their own
# and so do not appear above:
#
#   - `emit_render` (the `to_str` builder) — **done**, see its section above. It
#     drove `str_alloc` and the `write_*` cursors, which are `Word`-typed because
#     they traffic in raw pointers, so no symbol swap could have covered it; the
#     `aipl2_str_alloc`/`str_write_ptr`/`str_grew` trio replaced that idiom.
#   - Element helpers for containers holding a `str` — arrays, sets, dicts.
#
#     **Arrays are done.** `str[]` and nested `char[]` now select
#     `aipl2_arr_drop_str` / `aipl2_arr_retain_str`. The subtlety is *where*:
#     these pointers are stored in the array header and called by the runtime, so
#     they never pass through `active_sym` and the wide symbol has to be named at
#     the selection site (`array_drop_fn_addr` / `array_retain_fn_addr`). It is
#     chosen per **element type**, not per symbol, because `aipl_arr_retain_ptr`
#     serves `str` *and* array elements and only the `str` use changes shape — a
#     blanket remap would have corrupted every array-of-arrays.
#
#     **Sets and dicts are done** — see the cluster note above. No new symbols
#     were needed in either runtime: widening `str_cmp` from a flag to a width
#     gave both halves the discriminator, and the union loops now pass elements
#     by address instead of copying them into an `i64` (which kept only the first
#     word of a wide value).
#
#     `str?` elements are done too: `aipl2_arr_drop_opt_str` /
#     `aipl2_arr_retain_opt_str`, 32 bytes wide (tag + 24).
#
# Suggested order: the eleven queries first (no ownership, immediate signal from
# the corpus), then iteration, then the producers, then `emit_render`, then the
# containers — leaving concat and the file/test-runner ops last, since they are
