  `render` is for floats only (its body writes a float, and a body is compiled for every instance), so `render(7)` is a compile error rather than `to_str`'s "7"; the other options TODO.txt lists (leading +, exponent form) are more keywords on it
  an error raised inside an AIPL builtin's body when an instance is compiled (not at the call) carries a span from the builtin's source, drawn against the user's file (a caret past the end of the line): render now checks its float requirement at the call; the others are unaudited
generics:
  `a.count > b.count` on a `<N: ord>` type parameter is refused in the generic body ("comparison operand: expected i64, got type parameter N"), so a generic ordering cannot be written; ord bounds only reach `sort`/`maximum`-style builtins
  an integer literal in a generic struct literal does not flex to the declared field type: `let xs: Counted<u64>[] = [Counted { name: "x", count: 1 }]` says "declared Counted<u64>[], but its value is Counted<i64>[]"
lexer / parse_json:
  the per-byte cache and the rules' first-byte sets are rebuilt for every `lex_all`, so a source of a few tokens still pays for them (the lexer's own test case, over five-rule rule sets, costs 49% more instructions, and lex_aipl's 15%); the rules themselves are rebuilt per call too (`aipl_rules()`, `json_rules()`), and a constant cannot hold a computed value


optimizer / destination-passing:
  arrays/extend/extend_reserves_once regressed 218 -> 427 instructions (code 1008 -> 1760) in Round 1; uninvestigated
  `$into` variants for optional and result producers
  leading-spread literals (`[..xs.map(f).join(), b]`) still build then copy
  unchecked push (Round 3 of the $into project)

diagnostics:

codegen/types:
  `let gap = to_str(c).repeat(n);` then `match (d) { A => `{gap}{s}`, B => `{s}{gap}` }` renders gap as `['x', 'x']` (a char array) instead of its text; `let gap: str = ..` avoids it (builtin_pad.aipl carries the annotation). Likely the sunk/inlined `repeat` loses its str-ness in the interpolation
