The redundant_slice_bound lint: a slice that says in its bounds what the open-ended form already says. Three shapes, told apart by which bound is redundant, and a slice is at most one of them:

  • x[0..], x[..x.len()] and x[0..x.len()] cover the receiver end to end, which is what x

already is. The slice is not free: an array slice allocates a fresh block and copies every element, so this is a redundant copy as well as a redundant spelling. Dropping it is safe because arrays have value semantics — mutating an aliased binding copies first, so y = x cannot be surprised by a later set x[..]. A start of 0 counts however it was written. The hit points at a bound rather than the whole slice, because #[allow] is line-scoped and a receiver may span lines while a bound sits inside the brackets: the written 0, or when the start was left out (x[..x.len()]), the end bound, which must be there in that form.

  • x[y..x.len()]: the end bound is the receiver's own length, which is what the open-ended

x[y..] already means. The hit points at the end bound.

  • x[0..y]: a start of a written 0 is what the open-ended x[..y] already means. The hit

points at the 0.

The whole receiver is the first shape wherever it applies, so a full-range slice produces exactly one hit whichever way it was written, and its advice (x) is not the x[0..] or x[..x.len()] the other two would have started a second round trip on. Purely syntactic: the receiver and the len argument must be the same expression, so aliases or computed receivers that merely happen to be equal at runtime are not flagged.
