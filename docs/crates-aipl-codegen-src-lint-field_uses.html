How a name is used inside an expression, for the lints that turn a binding into a pattern.

destructure_binding asks it of a let and destructure_param of a parameter, and both put the same question: is every use of the name a field read, and are the names a pattern would bind free? What they share lives here; each lint keeps what only it asks.

is_shared fn 

pub fn is_shared(self: str[], everywhere: Read[], inside: Read[]) -> bool

Whether one of self is read off more than one base, discounting the reads in inside — a let's own right-hand side, whose reads run before the pattern binds anything. A pair read as often inside as anywhere has no read outside it, so it counts for nothing.

is_tuple_field fn 

pub fn is_tuple_field(self: str) -> bool

Whether self is a tuple position (t._0).

No struct pattern can take a tuple apart — there is no type name to write — and let (a, b) = t; has to name every position, where the lints see only the ones that were read. So tuples are left alone rather than advised into a pattern that would not compile.
