The AIPL implementation of the distinct builtin. The loader names this function by the canonical name __builtin_distinct (see aipl_syntax::builtin), so a user's xs.distinct() specializes through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It keeps the order the elements first appear in, which is what a set does not promise: to_set on an unordered set gives none, and an ordered one gives sorted order, which a type without < cannot have. In exchange it compares each element with the ones kept so far, so it costs one comparison per kept element per input element; for a large array of something with an order, to_set is the cheaper way to the same elements.

No lint steers the longhand here: the loop that keeps an element unless it was already kept has too many spellings (contains or any on the array, has on a set kept alongside, a guard that also does other work) for a shape that could be advised precisely, and a mis-advised lint is worse than none.

pub fn distinct<T: any>(self: T[]) -> T[]

self without its repeats: each element once, in the order it first appears. Elements are compared with ==, so a type that has none (a float) is refused. Callable as a method.
