Operators that come in more than one flavor (wrapping_add and saturating_add) are bound by import, and nothing fixes which flavor a file chose for +. A lint that advises another spelling of the same arithmetic — set x = x + 1; as set x++;, or as set x += 1; — is only right when the spelling it advises has the flavor the file's operator has, and it is the import that names it. This is where that is decided, so each such lint asks the same question the same way.

paired fn 

pub fn paired(self: Item[], written: str, target: str) -> Pairing?

How items can be advised to write target where they write written, or none when there is nothing that provably means the same.

The written operator has to be the file's own and a builtin: a user function of that name has no flavor to pair with. Where target has only one flavor there is nothing to choose and it is that one; where it has several, the one sharing the written operator's flavor is the one that means the same. A target the file already imports counts only if it is that builtin — one bound to the other flavor, or to a function of the file's own, would not mean what the advice says.
