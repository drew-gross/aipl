The span is this node's token span: every token the node was built from, closing bracket and unary operator included. A span kept for diagnostics alone can be narrower than that — it only has to point somewhere useful — but a formatter needs the extent, so this one records it.

value_span is a block's tail position: fn f() -> str { let a = 1; a } returns the a, but the body's span starts at the let, so a return-type error would underline the binding. It is recorded while the block is being built, where the tail is in hand, rather than re-walked at every diagnostic.

Rust spells it Option<Box<Span>>; here it is a plain Span with the empty one meaning "none", which is the convention already in force for a location that does not exist (see join_spans). A struct field could not be an optional struct when this was written, so there was no choice; it can be one now, and the two spellings mean the same thing either way, since a recorded value span is never empty: the repair that fills it in runs first.

The ty field Expr carries in Rust is absent — nothing the parser sets it.

ExprKind variant 

variant ExprKind

aipl_syntax::ast::ExprKind, all 32 cases.

Several surface forms are gone by the time they get here, because the AST is where the language stops having them: an operator is an Call on its spelling, a range is an Construct of the builtin Span, a template is a chain of concat calls, and a block is a right-nested Seq. Each is done in the lowering, so nothing downstream has to know the surface form existed.

Call's method_style is the one bit that says which spelling was written: recv.f(a) is stored as the free call f(recv, a) with the flag set, so the receiver is args[0] either way.

Destructure variant 

variant Destructure

What a let, a for or a parameter takes a value apart with, as written. A tuple's slots are its positions, so only the names are kept; a case's payload is bound in order; a struct names the fields it reads and what each is bound as, and mutable is the mut T { .. } = v form.

  • ByTuple(names: str[])
  • ByCase(case_name: str, names: str[])
  • ByStruct(struct_name: str, fields: str[], names: str[], mutable: bool)
  • ByPattern(pattern: Pat)

    A pattern with something nested in it, Case(Point { x, y }) or (Point { x }, n), which the forms above cannot spell. It is read the way a match arm is, so it is any pattern an arm takes; whether it can fail to match is for the type checker to say, as it is for ByCase.

join_spans fn 

pub fn join_spans(a: Span, b: Span) -> Span

Two spans as the one that covers both — aipl_syntax::join_spans, mirrored.

The rule that matters is the empty one: an empty span is the "no location" placeholder a construct with no text of its own carries (an empty block body, a synthesized node), and it must not take part in a join. Written naively as a.start..b.end it drags every enclosing construct's end back to offset 0, which is a span that ends before it starts — and a caret rendered from one is nonsense. Contributing nothing is the honest answer.

show_expr fn

An expression as a one-line structural dump. Spans are left out: they are what 5e has to settle and what would make every assertion unreadable in the meantime, and none of them is what a lowering test is asking about.

map_subexprs fn 

pub fn map_subexprs(self: Expr, f: (Expr) -> Expr) -> Expr

self with f applied to each of its direct sub-expressions, and nothing else changed: not self's own kind payload (names, types, patterns), not its spans, and not the sub-expressions' own children — a pass that wants to reach those recurses through f.
