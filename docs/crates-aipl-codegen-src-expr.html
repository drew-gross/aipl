The span is this node's *token* span, which is a superset of gazelle's: gazelle's are kept for diagnostics rather than as a record of extent, so a bracketed form's stops before its closing bracket and a unary leaves its own operator out. aipl_spans_contain_gazelles is where that is stated and checked; 5e in PARSER_LIBRARY.md is where it is argued.

value_span is a block's tail position: fn f() -> str { let a = 1; a } returns the a, but the body's span starts at the let, so a return-type error would underline the binding. It is recorded while the block is being built, where the tail is in hand, rather than re-walked at every diagnostic.

Rust spells it Option<Box<Span>>; here it is a plain Span with the *empty* one meaning "none", which is the convention already in force for a location that does not exist (see join_spans). A struct field cannot be an optional struct anyway — see the constraint list in PARSER_LIBRARY.md — and the two spellings mean the same thing, since a recorded value span is never empty: the repair that fills it in runs first.

The ty field Expr carries in Rust is absent — nothing the parser sets it.

One arm of a match, and the then half of an if let. Its span is the *pattern's*, so a diagnostic points at what selected the arm rather than at everything it does.

ExprKind variant 

variant ExprKind

aipl_syntax::ast::ExprKind, all 32 cases.

Several surface forms are gone by the time they get here, because the AST is where the language stops having them: an operator is an Call on its spelling, a range is an Construct of the builtin Span, a template is a chain of concat calls, and a block is a right-nested Seq. That is the same set of desugarings gazelle's build actions do, in the same places.

Call's method_style is the one bit that says which spelling was written: recv.f(a) is stored as the free call f(recv, a) with the flag set, so the receiver is args[0] either way.

show_expr fn 

pub fn show_expr(self: Expr) -> str

An expression as a one-line structural dump. Spans are left out: they are what 5e has to settle and what would make every assertion unreadable in the meantime, and none of them is what a lowering test is asking about.

A free call renders f(a, b) and a method call a.f(b), so the method_style flag is visible without a tag of its own — the two spellings are the two things it distinguishes.
