The AIPL implementation of the opt_right_fold builtin: right_fold with a fallible combiner, and the mirror of opt_left_fold (see builtin_opt_left_fold.aipl). Monomorphization registers this function under the canonical name __builtin_opt_right_fold (see AIPL_BUILTIN_SOURCES in lib.rs).

Walks the indices backwards, stopping at the first none — AIPL has no break, so the short-circuit lives in the while condition. Nothing is allocated (no reversed copy). self[i] yields an optional and i is always in range, so that inner none arm is dead.

The accumulator stays a plain A — the ok flag, not an A? threaded through the loop, carries the failure. A mut binding of an optional (a composite) reassigned from inside a loop body is currently miscompiled: the body's scope releases the new value's heap components while the binding still points at them, so a str/array/boxed accumulator would corrupt. A plain A binding goes through the slot-owned-reference model instead, which is correct across scopes.

opt_right_fold fn 

pub fn opt_right_fold<T: any, A: any>(self: T[], init: A, f: (T, A) -> A?) -> A?

Combine the elements right to left with a fallible combiner, starting from init: f takes the element first and the accumulator second (the mirror of opt_left_fold) and returns A?; the first none ends the fold with none, and the elements to its left are never visited. An empty array folds to some(init).

Prefer opt_left_fold (imported as plain opt_fold) unless the right-to-left order matters.
