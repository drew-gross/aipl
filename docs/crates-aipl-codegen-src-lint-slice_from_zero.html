The slice_from_zero lint: x[0..y] — a start bound of a written 0 is what the open-ended x[..y] already means. The mirror of slice_to_len, and it leans on the same distinction: an omitted start is a zero with an empty span, so requiring a non-empty span is what separates a written 0 from an elided one.

Only flagged when there is an end bound. x[0..] is left alone here on purpose: x[..] is not a form, so there would be nothing to recommend (slice_whole reports it, since a zero start makes it the whole receiver). Nor is x[0..x.len()], which is the whole receiver in one step rather than the two this lint's x[..x.len()] would start.

The hit points at the 0.
