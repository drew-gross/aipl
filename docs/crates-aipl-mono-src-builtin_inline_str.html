The AIPL implementation of the inline_str builtin. Monomorphization registers this under the canonical name __builtin_inline_str (see AIPL_BUILTIN_SOURCES in lib.rs), so a user's s.inline_str() resolves through the ordinary machinery.

It is the one member of the *_str family written in AIPL rather than as a runtime entry point, because it is the one that can fail: an inline value holds its content in the value's own words, so content past that capacity has no inline form at all. The two halves it is built from — pack_inline, which packs without checking, and inline_capacity, the bound — are internal for that reason: each is only sound behind the other.

No lint. The shape this replaces is a reliance, not a spelling: a short literal is already inline, so the longhand is an ordinary literal plus a reader who knows the capacity. There is no syntax to match on.

inline_str fn 

pub fn inline_str(self: str) -> str?

The content of self packed into the value's own words — no allocation and no refcount — or none when it is longer than an inline value can hold.

The optional is the capacity: heap_str and rope_str answer at every length, and this one cannot, so it says so rather than quietly handing back the representation self already had. Asking for an inline value and getting a buffer is the failure the whole family exists to rule out.
