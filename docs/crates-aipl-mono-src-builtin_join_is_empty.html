The AIPL implementation of the join_is_empty builtin — the other half of join_is_nonempty (see builtin_join_is_nonempty.aipl, which says what the fusion is for and what rule decides it). The loader names this function by the canonical name __builtin_join_is_empty (see aipl_syntax::aipl_builtins), so a user's xs.join_is_empty(sep=s) resolves through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It is what xs.join(sep=s).is_empty() means, without building the join. The compiler's operation-fusion pass writes it for that chain (see chain_fusions in aipl-mono); also callable directly.

pub fn join_is_empty<T: any>(self: T[][], sep: T[] = [], final_sep: T[] = sep, only_sep: T[] = sep, leading_sep: bool = false, trailing_sep: bool = false) -> bool

True when self.join(..) with these separators has no elements: every piece is empty and so is every separator join would write between or around them. Exactly the negation of join_is_nonempty, which owns the rule.

  • self: T[][]
  • sep: T[] = []

    Written between consecutive pieces, and at the ends when leading_sep or trailing_sep is set; defaults to empty.

  • final_sep: T[] = sep

    Written in the last gap instead of sep.

  • only_sep: T[] = sep

    Written in the sole gap of a two-piece join instead of sep.

  • leading_sep: bool = false

    Write sep before the first piece (when there is one).

  • trailing_sep: bool = false

    Write sep after the last piece (when there is one).
