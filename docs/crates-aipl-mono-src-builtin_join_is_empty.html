The AIPL implementation of the join_is_empty builtin — the other half of join_is_nonempty (see builtin_join_is_nonempty.aipl, which says what the fusion is for and what rule decides it). Monomorphization registers this function under the canonical name __builtin_join_is_empty (see AIPL_BUILTIN_SOURCES in lib.rs), so a user's xs.join_is_empty(sep=s) resolves through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It is what xs.join(sep=s).is_empty() means, without building the join. The compiler's operation-fusion pass writes it for that chain (see chain_fusions in aipl-mono); also callable directly.

pub fn join_is_empty<T: any>(self: T[][], sep: T[] = [], final_sep: T[] = sep, only_sep: T[] = sep) -> bool

True when self.join(sep=sep, final_sep=final_sep, only_sep=only_sep) has no elements: every piece is empty and so is every separator join would write between them. Exactly the negation of join_is_nonempty, which owns the rule.
