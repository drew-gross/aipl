Walk struct 

struct Walk

The state threaded through the line walk: the rewritten file so far, whether the current line is inside an old body being dropped, and the fills that haven't met their header yet (whatever is left gets appended at the end).

The fills are a dict, section name to body, which is what they are: one body per section, looked up by name. They were a Fill { section, body }[], which had to be searched for the name on every line of every file, filtered to drop a match, and could hold two bodies for one section with nothing to say which of them won.

fill_or_add_sections fn 

pub fn fill_or_add_sections(contents: str, fills: #{str: str}) -> str

Rewrites contents so that every section named in fills holds that fill's body: an existing --- section --- block has its old body (up to the next header line or EOF) replaced, and a section the file doesn't carry is appended as a fresh block. Everything else is preserved verbatim.

The whole batch costs one walk, which is the point: a case whose stdout, exit code and performance all went stale is read, rewritten and written back once rather than three times.

step fn 

fn step(w: Walk, line: str) -> Walk

Fold one source line into the walk. A header line named by a pending fill is re-emitted with that fill's body under it, and everything up to the next header is dropped; any other line passes through unless it sits inside a body already being dropped.

append_missing fn 

fn append_missing(out: str, pending: #{str: str}) -> str

Append a fresh --- section --- block for every fill the file carried no header for, after dropping the trailing newlines the walk copied over.
