What the three as_case lints on a match or let .. else share: recognising a variant case's pattern, the arm that gives up with none, the places where a ? would leave the function with the answer the construct had, and the statement that advice spells.

CasePattern struct 

struct CasePattern

A constructor pattern for a case of a variant the program declares: its name, and the names it binds (none for K(..) or a case with no payload).

case_pattern fn 

pub fn case_pattern(self: Pat) -> CasePattern?

self as a [CasePattern], when it is one. some, none, ok and err are optionals and results rather than cases of a declared variant, and a bare lowercase name binds rather than naming a case. A slot written _ makes the pattern a Nested one rather than a Ctor, but it still only takes the payload apart by position, as as_case and a let do; a slot over a real sub-pattern does not.

is_give_up fn 

pub fn is_give_up(self: MatchArm) -> bool

Whether self is the catch-all arm that gives none: _ => none.

tail_matches fn 

pub fn tail_matches(self: Expr) -> Expr[]

The match and if let expressions in self whose value is self's: the tail of a body, through the statements that lead to it, the branches of an if, and the arms of another match. A ? written in place of such an expression returns from the function with the same answer it would have produced.

statement_head fn 

pub fn statement_head(self: CasePattern) -> str

The statement that takes a case apart, as far as it precedes the receiver and as far as it follows the case: let Circle(r) = and ?;, or nothing before the receiver when the pattern binds nothing. The advice quotes the receiver and .as_case(Circle) between them.
