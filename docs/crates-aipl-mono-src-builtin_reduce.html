The AIPL implementation of the reduce builtin. The loader names this function by the canonical name __builtin_reduce (see aipl_syntax::aipl_builtins), so a user's xs.reduce(step) resolves through the ordinary generic / higher-order machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It is the one implementation of every reduction. A builtin that reduces a sequence to one value — minimum, maximum — has no body of its own: the compiler lowers xs.minimum() to xs.reduce(min) (see Callee::reduction_step and lower_reductions in aipl-mono), so each reduction is just a name for a step, and the step's own implementation is the only code that distinguishes it. map_reduce and filter_map_reduce are this with a mapping (and a filter) in front, and the fusion pass writes them for exactly those chains.

reduce fn 

pub fn reduce<T: any>(self: T[], step: (T, T) -> T) -> T?

The elements combined left to right with step, seeded by the first: for [a, b, c], some(step(step(a, b), c)). step is never called on fewer than two elements; one element is itself, and an empty receiver is none.
