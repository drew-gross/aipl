The lints, run over a parsed file.

squelch is applied to what these return: it drops the hits an #[allow] marker covers and says how to keep the rest. A lint is added by giving it its own file and an entry in all_lints; the hits come back in the order the lints are listed.

all_lints fn 

pub fn all_lints() -> Lint[]

Every lint of one function, under the name of its file, in the order its hits are reported. A lint of one kind of node is run over each node of that kind in a function's body; one that finds at most one hit is written [..hit] to say so.

lint_with_unfilled fn 

pub fn lint_with_unfilled(src: str, names: str[]) -> LintHit[]!ParseFailure

What the lints named names say of the program src parses to, as they say it, before any file's imports decide how they are written. Every builtin counts as imported, so a lint's own tests are about the shape it finds and nothing about imports, or about any other lint.

lint fn 

pub fn lint(program: ResolvedProgram) -> FilledHit[]

Every hit the ported lints find in program.

A lint is either a function of the whole program or of one function. The program's functions are listed once, and each function lint is run over them: every body that is code.

lint_str fn 

pub fn lint_str(src: str) -> str[]!ParseFailure

The messages every lint reports for the program src parses to, which is how a lint's own tests read what it says: they run all the lints, so a snippet must be one no other lint objects to.
