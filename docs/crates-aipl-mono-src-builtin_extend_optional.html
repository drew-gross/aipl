The AIPL implementation of the extend_optional builtin — the T? shape of extend's variadic source, for an array receiver. Monomorphization registers this function under the canonical name __builtin_extend_optional (see AIPL_BUILTIN_SOURCES in lib.rs), and mono's Extend arm is what resolves a set xs.extend(maybe) onto it; the in-file name is only for this file's own tests, which read exactly like the user code that never spells it.

Internal (INTERNAL_BUILTINS), so the import is refused everywhere but a builtin_*.aipl source: extend is the spelling, and a second name for one of its shapes would be the hand-rolled helper this replaced.

It is a push and not an extend of a one-element sequence, which is the whole reason it exists. extend sizes the destination to exactly old + source.len(), so a one-element source reallocates on every append — measured on lexer.aipl, 10 reallocations became 112 — while push grows geometrically and needs no temporary sequence to hold the one element.
