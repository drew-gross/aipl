What the lints on a binding seeded and then filled by the loop that follows it (push_loop_pipeline, extend_loop_map_join, push_loop_collect_ok, union_loop_union_all) share: recognising the seed and the loop, and phrasing the pipeline that loop is. For an array filled with one expression per element:

mut out = [];
for (let x : xs) {
    if (keep(x)) {
        set out.push(f(x));
    };
}

The shape has to be exactly this, because anything else in the loop is something the pipeline would drop: the loop body is one statement (the add, or an else-less if around one add), the guard and the added value may not mention out, and may not use ?, which would return from the lambda they move into instead of the function. What comes after the loop is unconstrained — a later set out.push(..) is fine, since the rewrite leaves out a mut binding that simply starts out filled.

seeded_loops fn 

pub fn seeded_loops(self: Expr) -> SeededLoop[]

Every [SeededLoop] in self and under it. The loop has to be the very next statement: one between the two could read the binding while it is still empty, which the rewrite would reorder. An indexed loop is not this shape: map and filter pass each element and have no index to pass with it, so the rewrite would silently drop whatever the body did with it.

pipeline_hit fn 

pub fn pipeline_hit(self: SeededLoop, what: str, annotation: str, stages: (str, str)[]) -> UnfilledHit

The hit for a loop that is the pipeline of stages over its iterable, assigned to the binding: what is how the loop fills it, as the message says, and annotation what follows the binding's name in the advice. Each stage is a builtin and the arguments it is written with. It points at the seed, not the loop: #[allow] is line-scoped, so a hit spanning the loop could never be squelched (the marker would have to go on the for (..) { header, and the formatter relocates one written there onto a line of its own, where it squelches nothing). mut out = []; always occupies one line, and is where the shape starts.
