What the two loop-accumulation lints (push_loop_pipeline, extend_loop_map_join) share: recognising an array that is seeded empty and then filled by the loop that follows it and nothing else, and phrasing the pipeline that loop is.

mut out = [];
for (let x : xs) {
    if (keep(x)) {
        set out.push(f(x));
    };
}

The shape has to be exactly this, because anything else in the loop is something the pipeline would drop: the loop body is one statement (the add, or an else-less if around one add), the guard and the added value may not mention out, and may not use ?, which would return from the lambda they move into instead of the function. What comes after the loop is unconstrained — a later set out.push(..) is fine, since the rewrite leaves out a mut binding that simply starts out filled.

pipeline_hit fn 

pub fn pipeline_hit(self: Accumulation, stages: (str, str)[]) -> UnfilledHit

The hit for a loop that is the pipeline of stages over its iterable, assigned to the array: each stage a builtin and the arguments it is written with. It points at the seed, not the loop: #[allow] is line-scoped, so a hit spanning the loop could never be squelched (the marker would have to go on the for (..) { header, and the formatter relocates one written there onto a line of its own, where it squelches nothing). mut out = []; always occupies one line, and is where the shape starts.

lone_statement fn 

fn lone_statement(self: Expr) -> Expr?

The one statement a block consists of, or none when it holds anything else — no statements, or more than one. A block is a right-nested chain, and which node carries the rest of it depends on the statement: an expression statement is a Seq whose second operand is the remainder, while an assignment holds its own. Only those two forms are recognized, and each is "lone" exactly when what follows it is the block's tail.

is_block_tail fn 

fn is_block_tail(self: Expr) -> bool

Whether self is what the parser ends a statement-only block with: () for an ordinary block, and an 0 with no location of its own — the loop expression's result — for a loop body, which may not end in a value of its own at all. The loop's zero is told from a written one by its empty span, the way slice_from_zero tells an elided slice bound from a typed one.

fn added_to(self: Expr, acc: str, adder: str) -> Expr?

The value adder adds, when self is set acc.adder(value); — acc = adder(acc, value) — and nothing else.

fn is_liftable(self: Expr, acc: str) -> bool

Whether self can move into a lambda in a rewritten pipeline: a ? returns from the function it is written in, so moved into a lambda it would return from the lambda instead, and the rewrite no longer has acc, the array being filled.
