The match_only lint:

match (xs) { [x] => some(x), _ => none }

— an array's one element, and none when it holds none or several. That is exactly xs.only(). With a fallback in place of none,

match (xs) { [x] => x, _ => d }

it is xs.only().value_or(d).

The [x] arm has to be one plain name and hand it back unchanged, bare or in some(..): an arm that does something with the element is a map over what only finds, which is not this lint's to advise. The default is held to the bar match_value_or holds its own to (is_constant_default), since value_or's default is evaluated whether or not the array held one element; and none is not a default there, where the answer is an optional of its own.

The hit points at the catch-all arm's body, one short expression on one line, so #[allow] squelches it.
