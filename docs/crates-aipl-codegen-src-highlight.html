matcher_pat fn pub 

pub fn matcher_pat(m: Matcher, scope: str, esc_scope: str) -> Pat

The TextMate pattern recognizing what m matches, painted scope. A matcher that scans between delimiters becomes a Region, and esc_scope is what its escape sequences are painted (constant.character.escape.*); every other matcher becomes a plain Match.

Total over Matcher, so a new matcher shape in lexer.aipl fails to compile here until it has a highlighting answer.

matcher_regex fn pub 

pub fn matcher_regex(m: Matcher) -> str?

The plain regex m matches, or none when m scans between delimiters and needs a whole region rather than one expression. The way to reuse a rule's own character classes in a pattern written by hand — a fn NAME declaration accepting exactly the names the identifier rule accepts.

rule_pats fn pub 

pub fn rule_pats<K: any>(rules: TokenRule<K>[], esc_scope: str) -> Expansion

The patterns rules describes, in rule order — one per rule, except that a run of consecutive rules sharing a scope collapses into a single ordered alternation, which is what turns twenty Keyword rules into one \\bfn\\b|\\blet\\b|... Rules with no scope (whitespace, anything a highlighter should not paint) are dropped.

Order is preserved exactly, and regex alternation is ordered too, so a rule list written longest-spelling-first stays maximal munch. esc_scope paints the escape sequences inside delimited literals.

A self-referential region — a nestable block comment — comes back as an Include plus the named entry it refers to, since that shape cannot be written inline.

decl_pat fn pub 

pub fn decl_pat(keyword: str, name_re: str, kw_scope: str, name_scope: str) -> Pat

A declaration: keyword then a name matching name_re, with the two halves painted kw_scope and name_scope. This is the one genuinely *syntactic* thing a highlighter does — a name means something different for standing after fn — and the only one a regex- and line-based target can express.

Pass name_re from the identifier rule's own matcher (matcher_regex) so the names a declaration accepts stay the names the lexer accepts. It must contain no capture groups of its own, which a character-class run never does.

word_pat fn pub 

pub fn word_pat(words: str[], scope: str) -> Pat

An alternation of whole words, all painted scope — for a class the lexer does not distinguish because it is decided after lexing, like the builtin type names that are lexically just identifiers.
