Tm struct 

struct Tm

A whole TextMate grammar. top is the pattern list applied to a file, and repo the named entries it and they reach through Include — including the conventional main, which is where a language's own patterns live so that a string interpolation can include the whole language back into itself.

note becomes the top-level comment key, which the format reserves for exactly this and every consumer ignores. A generated file that does not say it is generated gets hand-edited, so it is not optional in practice.

matcher_pat fn 

pub fn matcher_pat(m: Matcher, scope: str, esc_scope: str) -> Pat

The TextMate pattern recognizing what m matches, painted scope. A matcher that scans between delimiters becomes a Region, and esc_scope is what its escape sequences are painted (constant.character.escape.*); every other matcher becomes a plain Match.

Total over Matcher, so a new matcher shape in lexer.aipl fails to compile here until it has a highlighting answer.

matcher_regex fn 

pub fn matcher_regex(m: Matcher) -> str?

The plain regex m matches, or none when m scans between delimiters and needs a whole region rather than one expression. The way to reuse a rule's own character classes in a pattern written by hand — a fn NAME declaration accepting exactly the names the identifier rule accepts.

brace_group_entry fn 

pub fn brace_group_entry(punct_scope: str) -> Entry

The repository entry an interpolation nests braces through: a { .. } whose inside is the language again, itself included, so {#{1, 2}} and {P { x: 1 }} balance to the interpolation's own closing brace. A grammar with templates has to carry this entry, since template_inner refers to it.

The region is scoped as punctuation for the sake of its two braces — the only way to paint the closing one, since the model has no end capture — and every token between them is painted over by main's own patterns.

Expansion struct 

struct Expansion

What a rule set expands to: the patterns, in rule order, and the repository entries some of them need names for. A self-referential region can only be written as a named entry that includes itself, so the expansion cannot be a bare pattern list.

Item struct 

struct Item

One scoped rule reduced to what the merge below needs: its pattern, its scope, the regex when the pattern is a plain Match, and whether it has to become a named entry.

rule_pats fn 

pub fn rule_pats<K: any>(rules: TokenRule<K>[], esc_scope: str) -> Expansion

The patterns rules describes, in rule order — one per rule, except that a run of consecutive rules sharing a scope collapses into a single ordered alternation, which is what turns twenty Keyword rules into one \\bfn\\b|\\blet\\b|... Rules with no scope (whitespace, anything a highlighter should not paint) are dropped.

Order is preserved exactly, and regex alternation is ordered too, so a rule list written longest-spelling-first stays maximal munch. esc_scope paints the escape sequences inside delimited literals.

A self-referential region — a nestable block comment — comes back as an Include plus the named entry it refers to, since that shape cannot be written inline.

decl_pat fn 

pub fn decl_pat(keyword: str, name_re: str, kw_scope: str, name_scope: str) -> Pat

A declaration: keyword then a name matching name_re, with the two halves painted kw_scope and name_scope. This is the one genuinely *syntactic* thing a highlighter does — a name means something different for standing after fn — and the only one a regex- and line-based target can express.

Pass name_re from the identifier rule's own matcher (matcher_regex) so the names a declaration accepts stay the names the lexer accepts. It must contain no capture groups of its own, which a character-class run never does.

word_pat fn 

pub fn word_pat(words: str[], scope: str) -> Pat

An alternation of whole words, all painted scope — for a class the lexer does not distinguish because it is decided after lexing, like the builtin type names that are lexically just identifiers.

A backslash followed by one of escapes — what a delimited scan treats as an escape rather than as content.

template_inner fn 

fn template_inner(escapes: str, esc_scope: str) -> Pat[]

What lies inside a template literal: its escapes and the { .. } interpolation, which includes the whole language back into itself so an interpolated expression keeps its ordinary scopes. The escapes always include the template's own \{/\} (see Template in lexer.aipl), listed ahead of the interpolation so an escaped brace is painted as one rather than opening it. The brace group comes first inside so a { .. } *inside* the expression — a set literal, a struct — closes itself rather than the interpolation; see brace_group_entry.

The repository entry name a scope makes: its parts joined with -, without the trailing language suffix — comment.block.aipl becomes comment-block. Only a self-referential region needs one, so this is the whole naming scheme.
