The set_spread_insert lint: set seen = #{..seen, x}; — a set rebuilt from itself only to add to it. set seen.insert(x); is the addition spelled as one: it names the element added, and the set's other contents never come up.

It is the set sibling of set_spread_push, and the argument is the same. The rebuild spelling says "build the larger set, then store it", which costs a fresh set of the combined size on every addition; insert writes into seen's own storage when nothing else holds it, and copies when something does, so the two spellings agree on what any other binding sees. A field path works the same way as a bare name (set self.seen = #{..self.seen, x} is set self.seen.insert(x)), which is the whole set of targets: insert writes the grown set back into the place it was given, and only a name or a field path off one is a place.

Three shapes are left alone. The spread must be the first element and must be the target itself — #{x, ..seen} is the same set but starts from x, and #{..other, x} starts from a different set, and neither is something insert can spell. A spread in the tail adds a whole set rather than one element (#{..seen, ..more}), which is union, so it is not advised here. And with more than one added element the rewrite is one call per element, so it is offered only when no element reads the target: set seen = #{..seen, seen.len(), seen.len()}; adds the same length twice, where the two inserts would see the set grow between them. A single element is always safe — it is computed before the addition either way.

The shape is all language syntax — a set literal with a spread in it needs no import — so the lint fires whether or not insert is imported. The name is only for the advice, which says to import it when it is missing.

The hit points at the spread, which is a single line however the literal is broken.
