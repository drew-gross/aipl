The AIPL implementation of the zip builtin. The loader names this function by the canonical name __builtin_zip (see aipl_syntax::builtin), so a user's xs.zip(ys) specializes through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

zip_with with the pairing function left out: it is the one to reach for when the pairs are what is wanted (to build a dict, to sort, to walk with a destructuring for), and zip_with when each pair is only going to be combined. A lint steers a zip_with whose function just builds the pair here (zip_with_pair_zip), and a loop that pairs by index (push_loop_zip_with).

The body is a loop rather than a zip_with call: the lint on that call would flag the builtin that it advises.
