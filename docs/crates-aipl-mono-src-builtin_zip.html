The AIPL implementation of the zip builtin. The loader names this function by the canonical name __builtin_zip (see aipl_syntax::builtin), so a user's xs.zip(ys) specializes through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

The pairs are what is wanted by default (to build a dict, to sort, to walk with a destructuring for), and with says what to make of each pair instead when it is only going to be combined: xs.zip(ys, with=|x, y| { x + y }). A lint steers a loop that pairs by index here (push_loop_zip_with).

The pairing function's default is a lambda, which the call fills in and types from the arrays it is given; its parameters need no types of their own. The body is a loop, so a call with a lambda with is specialized for it like any function that takes one.

zip fn 

pub fn zip<T: any, U: any, V: any>(self: T[], other: U[], with: (T, U) -> V = |first, second| { (first, second) }) -> V[]

The elements of both arrays combined pairwise by with, stopping at the shorter one: [1, 2, 3].zip(["a", "b"]) is [(1, "a"), (2, "b")], and [1, 2].zip([10, 20], with=|x, y| { x + y }) is [11, 22]. Callable as a method.

  • self: T[]
  • other: U[]

    The second array; the result stops at the shorter of the two.

  • with: (T, U) -> V = |first, second| { (first, second) }

    Called with the elements of both, pairwise. Defaults to making the pair.
