The push_loop_zip_with lint:

mut out = [];
for (let i, x : xs) {
    if (let some(y) = ys[i]) {
        set out.push(f(x, y));
    };
}

— an array seeded empty and filled by a loop that walks one array by position and, for each element the other array also has, pushes something derived from the pair. That is xs.zip_with(ys, |x, y| f(x, y)), which says the array is the paired elements, and xs.zip(ys) when what is pushed is just (x, y). Both stop at the shorter array, as the loop does: an xs longer than ys finds ys[i] missing from there on.

The shape has to be exactly this. The if let is what makes the loop stop at the shorter array; a ys[i].value_or(d) carries on past the end of ys with a default, which zip_with does not do, so it is not advised. Anything else in the loop is work the pipeline has nowhere to put, ys has to be a plain name (it is read once per element here and once in the rewrite, so a call would run a different number of times), and the pushed value may not read the array being built, the position, or use ?, none of which a lambda has.

What this cannot check is that xs and ys are arrays: a for also walks a str's bytes and a dict's keys (where the "position" is the key), and which it is only becomes known two passes later. Neither is an array for zip_with to take, and #[allow] is the answer there, as it is for push_loop_pipeline.

The hit points at the seed.
