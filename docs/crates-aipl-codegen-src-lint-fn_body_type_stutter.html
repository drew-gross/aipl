The fn_body_type_stutter lint: fn f() -> T { T { .. } } — a function whose whole body is a literal of its own declared return type, naming that type twice. The body-shorthand spelling drops the repetition: fn f() -> T { .. }.

Both spellings parse to the same Construct, so which one was written is recovered from the source: the long form's span starts at the type name, the shorthand's at the first field name. Requiring a { after that name is what keeps a field that happens to share the type's name from reading as the long form.

Only a body that is exactly the literal qualifies: a block with any statement in it parses to a Let/Seq wrapping the literal, and the shorthand replaces the whole body, so those are left alone. A destructured parameter is no statement either, which the surface tree this runs on makes true without looking through anything.
