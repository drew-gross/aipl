Where an expression is and what was written there — 12 v + 2 — which is the one thing the compiler's two source-text rewrites both need. The loader calls this through the FFI (see install_parser_hooks) while baking assert(cond) into __assert(cond, loc) and trace(expr) into __trace(msg), and prefixes the file's own name to what comes back: sub/lib.aipl:12 v + 2.

The file is not a parameter. A line and a span are properties of one text, so this takes the text and the span and nothing else; which file that text came from is the caller's to know, and the caller — unlike this — holds the path.

span is the expression's half-open byte range within src; both bounds clamp to [0, len] (and an out-of-order range collapses to "") via ordinary string-slicing semantics, so no manual clamping is needed here.
