The field_init_shorthand lint: Point { x: x } — a field initialized with the bare identifier of the same name; Point { x } is the same literal.

The shorthand lowers to exactly the tree the explicit form builds, so the two are indistinguishable by shape alone: the explicit form is recognized from the source, by a : right before the value (the shorthand's value is the field name, with no colon before it). A comment between the : and the value leaves the field alone, the conservative choice that never mis-flags a shorthand.

A literal the parser synthesizes from other syntax carries a __builtin_-prefixed name a user cannot write — a range start..end is __builtin_Span { start: start, end: end } — and its bound identifiers are not a written field: field, so those are skipped.

The hit points at the value.
