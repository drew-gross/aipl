The AIPL implementation of the map_to_dict builtin. The loader names this function by the canonical name __builtin_map_to_dict (see aipl_syntax::builtin), so a user's xs.map_to_dict(f) resolves through the ordinary generic / higher-order machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It is what xs.map(f).to_dict() means, without the array of pairs: map would build one (key, value) per element for to_dict to walk once and drop, where here each pair is bound as f produces it. Written by the compiler's operation-fusion pass for that chain (see chain_fusions in aipl-mono); also callable directly.

No lint steers a hand-written loop here: push_loop_pipeline already sends a building loop to map, from where the chain fuses.

self.map(f).to_dict(): every element through f to a (key, value) pair, bound in a dict as it is produced. As with to_dict, the last pair for a key wins and the key keeps the place of its first.
