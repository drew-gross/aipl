The unused_functions lint: a function that is not pub and that nothing else in the file mentions. Nothing outside the file can reach it, so it is dead code, and a lint rather than a warning for the reason unused_imports is: it misstates what the file does and outlives whatever once called it.

"Mentioned" is syntactic, as it is for imports: a call, a method call, a function used as a value, a shim binding, or a mention from a constant or a struct field's default all count. A function's own body does not, so recursion does not keep one alive. A .test or .benchmark block on it does, whether or not the block names it: a function that exists to be tested is used, and only one with neither a caller nor a test is dead. Two functions that mention only each other are not reported.

Unused means unreachable from the file's entry points, which are the functions that are not Private: pub ones, main, and the blocks check runs. A file with none is a bag of fixtures with nowhere to start from, and is left alone.
