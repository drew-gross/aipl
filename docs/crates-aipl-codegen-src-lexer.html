keep_skipped fn pub 

pub fn keep_skipped<K: any>(self: TokenRule<K>[]) -> TokenRule<K>[]

self with every skip rule turned into a trivia rule: nothing is dropped, so every byte of a lexed source is accounted for by some token or trivia record.

A compiler's rule set skips whitespace outright — it has no use for it, and recording it would cost every consumer something only one of them wants. A *lossless* consumer has the opposite need: a parser building a concrete syntax tree, or a formatter reproducing its input, must be able to put every byte back. Both read the one rule set through this, rather than the language keeping two of them.

lex fn pub 

pub fn lex<K: any>(self: str, rules: TokenRule<K>[]) -> LexResult<K>!LexError

Lexes self into a LexResult: the flat token list, plus the trivia side-channel, as described by the ordered rules. At each position the first rule whose matcher matches claims the token (so order is priority — keywords before identifiers, floats before ints); a skip: true rule consumes its match without producing anything (whitespace), and a trivia: true rule records its matches in the side-channel instead of the token stream (comments, lint markers). A Template rule emits several tokens per literal — head/middle/tail segments around the tokens of each {...} interpolation, which are lexed by this same rule set. Lexing fails with an err — a LexError carrying a message and the offending span — when a byte matches no rule or a matcher sees invalid input outright (an unterminated Delimited token).
