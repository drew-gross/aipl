The AIPL implementation of the insert builtin. The loader names this function by the canonical name __builtin_insert (see aipl_syntax::aipl_builtins), so a user's set seen.insert(x); resolves through the ordinary generic machinery — the in-file name insert is only for this file's own tests, which read exactly like user code.

pub fn insert<T: any>(self: #{T}, element: T)

Add element to the set self names. A set that already holds it is left as it was.

It is a mut self method, so it is written as a statement — set seen.insert(source); — and writes the grown set back into the place it was given, a name or a field path off one. It is set seen = #{..seen, source}; said once: the element added is the only thing the line names, and the set's other contents never come up. A set literal that spreads in another set (#{..seen, ..more}) adds a whole set at a time, which this does not; union is that.

An ordered set (#>{T}, #<{T}) is refused: the grown set is written back as an unordered one, and the checker reports it does not fit the ordered binding.
