The AIPL implementation of the render builtin. The loader names this function by the canonical name __builtin_render (see aipl_syntax::builtin), so a user's x.render(digits=1) resolves through the ordinary generic machinery — the in-file name is only for this file's own tests, which read exactly like user code.

render is to_str with options, for the output that wants a say in how a float is written where to_str always gives the one spelling that reads back as the same value. With no options it is to_str. The options are all keywords. It is for floats: its body writes one with a digit count, so another type does not compile.

No lint steers to_str calls to it: nothing about to_str is wrong, it is the one without options.

pub fn render<T: any>(self: T, digits?: u64 = none) -> str

The float self as text. With no options that is to_str(self): the shortest decimal that reads back as the same value.

  • digits: for a float, write exactly that many digits after the point, correctly rounded

from the float's exact value (halves to even: 0.25 is 0.2 to one digit, 2.5 is 2 to none), so render(1.0 / 3.0, digits=3) is 0.333. A count past the 1074 digits a float's exact value has gives the rest as zeros. NaN and inf have no digits.
