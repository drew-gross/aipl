The AIPL implementation of the fold builtin. The loader names this function by the canonical name __builtin_fold (see aipl_syntax::aipl_builtins), so a user's xs.fold(init, f) specializes through the ordinary generic / higher-order machinery — the in-file name is only for this file's own tests, which read exactly like user code.

The combiner takes the accumulator first and the element second whichever way the fold goes, so one function says what to do with each step and direction says where the walk starts.

pub fn fold<T: any, A: any>(self: T[], init: A, f: (A, T) -> A, direction: Direction = Left) -> A

Combine the elements one at a time into an accumulator that starts as init: from the left, for [a, b, c], f(f(f(init, a), b), c) — xs.fold(0, |acc, x| acc + x); from the right, f(f(f(init, c), b), a) — building a cons list front to back from an array, the case where the direction matters: xs.fold(Nil, |acc, x| Cons(x, acc), direction=Right). Callable as a method.

  • self: T[]
  • init: A

    The accumulator the first element met is combined with.

  • f: (A, T) -> A

    Combines the accumulator and an element into the next accumulator.

  • direction: Direction = Left

    Which end the walk starts at: Left (the default) at the first element, Right at the last.
