format_cst fn 

pub fn format_cst<K: variant, A: any>(g: Grammar<K, A>, src: str, node: Cst, space: (str, str) -> bool) -> Doc!ParseError

The Doc that lays node out, given the grammar it was parsed with.

space answers the one question a grammar cannot: whether a space belongs between two adjacent tokens. It is asked with the spellings on either side of the gap — space("+", "1") while laying out 1 + 1, space("(", "a") while laying out (a) — so a language brings one small function instead of a layout function per production. Where a production wants no spaces at all, that is Tight and the rule is never consulted.

g is linked here, so it may be handed over unlinked, exactly as parse_cst takes it. That is not a convenience: a group's style lives in groups, which only link fills, so an unlinked grammar would lay every bracket pair out against a table that is not there. Linking is idempotent, so a caller that linked already pays one walk and nothing else.

Fails only on a tree that does not belong to g — a node naming a production or a group index the grammar has no entry for, which a tree from parse_cst cannot be.

breaks_after fn 

fn breaks_after(src: str, at: u64) -> bool

Whether the source puts a line break right after position at, with only blanks in between — the end of a source line, in other words.

This tells a line comment from a block one without asking the language: a comment the author ended their line with must still end a line, or it swallows whatever the formatter puts after it. End of input counts, there being nothing left to swallow.

group_doc fn 

fn group_doc<K: variant, A: any>(g: Grammar<K, A>, src: str, gi: u64, open: Cst[], body: Cst[], close: Cst[], space: (str, str) -> bool) -> Doc!ParseError

A Group laid out: its brackets around its contents, on one line while they fit and otherwise one item per indented line.

The brackets are read off the node, not inferred from it. That is the whole difference a group makes here: it says which of its kids opened it and which closed it, so #{a} (a two-token bracket), |a, b| (the same token both ends) and match (e) { .. } (two pairs in one production) are all just groups, with nothing to guess and nothing to be wrong about.

wrapped fn 

fn wrapped(open: Piece[], mid: Piece[], close: Piece[], st: ListStyle, space: (str, str) -> bool) -> Doc

A bracketed list: open, the items, close — flat while it fits, otherwise one item per indented line with the brackets on their own.

The bracket runs are laid out Inline rather than concatenated raw, so a comment written against a bracket survives and the language's spacing rule still gets asked about a bracket spelled as several tokens.

list_items fn 

fn list_items(mid: Piece[], __spat$21107: ListStyle, space: (str, str) -> bool) -> Doc[]

The items between a pair of brackets, each laid out inline.

A token spelled like the style's separator ends the item it follows and is dropped; the style writes the separators back, which is what lets a list that breaks gain a trailing one it never had in the source. With an empty separator every token or child starts a new item instead, which is the juxtaposed list. A comment never starts one — it belongs to the item it was written against.

grammar_of fn 

fn grammar_of(layouts: Layout[], groups: ListStyle[]) -> Grammar<FKind, str>

A grammar of one production per layout, in order, so a hand-built Tree(i, ..) picks a layout by its index — followed by one throwaway production per group style, so a hand-built Group(i, ..) picks a style by its index too.

The styles cannot simply be handed over: groups is link's output, rebuilt from the rules every time, so the only way to put a style in the table is to write a rule that has one. The carrier productions are never matched against anything; they exist to be linked.
