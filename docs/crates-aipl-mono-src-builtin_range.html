The AIPL implementation of the range builtin. Monomorphization registers this under the canonical name __builtin_range (see AIPL_BUILTIN_SOURCES in lib.rs), so a user's xs.range() resolves through the ordinary generic machinery.

A Span rather than a type of its own, because the language already has one for exactly this: recv[span] slices by a Span, so 0..len is the span that names the whole receiver — which is what makes xs[xs.range()] the identity slice.

Array receivers only. self: T[] does not unify with str, a set or a dict, the other three things len accepts, so s.range() is not available — giving it them means the checker/codegen receiver dispatch len and is_nonempty carry, not a change here.

No lint. The shape this replaces is an indexed for whose body reads only the index, and tuple_slot_names in grammar_aipl.aipl was the sole instance in the whole corpus — every other indexed loop reads its element too, which range().map cannot express on its own. One site does not pay for a lint that would have to tell those apart.

range fn 

pub fn range<T: any>(self: T[]) -> Span

Every index of self, as the Span 0..self.len() — the half-open range its elements sit in, empty for an empty receiver.

Its reason to exist is map: a Span is mappable, so xs.range().map(|i| ..) is the index-wise counterpart of xs.map(|x| ..), and replaces the mut acc plus counted-for longhand. self is unread apart from its length — the point is the positions, so the element type never reaches the result.
