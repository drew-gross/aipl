How a lint's advice names the builtins its rewrite needs, and how the framework decides what to write for each.

A lint says which builtin its advice uses (a [Need]: the builtin's tag) and never how the file spells it. [spelled] decides, from the file's imports: the name the file already has one under, or the preferred spelling (the operator for an operator builtin, else the builtin's own name) with the import that makes it available. A spelling the file cannot take — the name is bound to something else, or an operator is bound to another flavor — is no spelling at all, and the advice that needed it is dropped, since a rewrite the file cannot write is no advice.

Operators that come in more than one flavor (wrapping_add and saturating_add) are bound by import, and nothing fixes which flavor a file chose for +. Each flavor is a builtin of its own with its own tag, so a lint that advises another spelling of the same arithmetic — set x = x + 1; as set x++; — names the builtin of the flavor of the call it read (WrappingAdd advises WrappingIncrement), and the file either has that operator or can take it.
