format_source fn 

pub fn format_source(src: str, width: u64) -> str!FmtError

Format AIPL source to the canonical style, at width. The output always ends in exactly one newline (an empty program formats to just that). The input's trailing --- section --- blocks are preserved byte-for-byte — they follow that newline, and whatever they end with is theirs; trailing whitespace in the source portion is removed (the language rejects it, so fixing it can't change an accepted program's meaning).

TokenFingerprint struct 

struct TokenFingerprint

A lexed source reduced to what a reformat must preserve: every non-import token **in order**, the import statements as a sorted multiset, and the comments as one too. Two sources with equal fingerprints hold the same code.

A token counts as its *value* (token_value), so the formatter's value-preserving whitespace edits inside a """ block are not flagged while any change to a literal's value is.

Three things a reformat is allowed to change, and each is why a part is shaped the way it is:

- **Imports are hoisted and sorted**, both the statements and the names inside one. So each statement collapses to its own tokens sorted and joined (import_signature) and the statements are then sorted among themselves — reordering is invisible, losing or changing a name is not. - **A trailing comma is normalized** (dropped when a list renders flat, added when it breaks), and a variant's **leading |** is the same normalization at the other end. Both are layout, so is_layout drops them before anything else — which also excludes the | between match-pattern alternatives. - **Comments move with the construct they are glued to**, which can reorder them against the tokens, so they are their own sorted multiset rather than part of rest.

Everything else is positional: rest catches a token the layout moved, not just one it lost.

verify_same_tokens fn 

fn verify_same_tokens(input: str, output: str) -> ()!FmtError

Refuse unless output holds exactly input's tokens and comments — exactly as TokenFingerprint defines it, which is where the three things a reformat is allowed to change are spelled out.

The three parts are reported separately so the message names what moved: a reordered statement is an import-hoisting bug, a reordered token is a layout bug, and they want different reading.
