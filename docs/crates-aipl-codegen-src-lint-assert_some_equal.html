The assert_some_equal lint: assert(x == some(v)) — a test asserting that an optional holds a value by comparing it with some(v). assert(x? == v) says it with one less constructor: ? ends the test, as a failure, when x is none, so the comparison that follows only has to say what x holds. It is how a test already reads a result (parse(s)? == v), and the error of one (parse(s)!? == "message") is the same shape.

Only the assertion's whole condition is looked at, and only in a test's own body: a helper declared inside a test, or a lambda, may return something ? has no business propagating a none from, and an assertion that is one part of a larger condition (a && x == some(v)) is not rewritten by moving the ?. Either side may be the some(..); two of them are left alone.

The hit points at the assertion, which is the line the #[allow] goes on.
