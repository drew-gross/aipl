The AST grammar_aipl.aipl lowers to — AIPL's own syntax tree, declared in AIPL. It mirrors aipl_syntax::ast (crates/aipl-syntax/src/lib.rs), which is the type the compiler's passes actually run on: the bridge marshals a value of this shape across the FFI and the Rust side rebuilds an ast::Program from it.

It is declared across several files, one per case family, because constructors share one namespace per file and the families reuse names (Str is a primitive, an expression and a pattern; Unit a type and an expression): prim.aipl, ty.aipl, expr.aipl, pat.aipl, suffix.aipl, brace_entry.aipl, bound.aipl, item.aipl and parsed.aipl. A file that needs two of a name renames one on import — which is why this one imports Ty as TyNode: its own Ty case wraps it.

Two rules keep the two declarations comparable by eye and, later, by test:

  • A case here is its Rust case name, bare. Type::Named is Named, Type::Optional is Optional, ExprKind::Call is Call. The mapping the FFI bridge (ffi_ast.rs) applies is the identity, so a case it does not know about is a case the two declarations disagree about.
  • Only what the parser can produce is declared. Type carries four sentinels no source text spells — NoneInner, EmptyArrayArg, NoneLiteralArg, ConcatStr — invented by the checker for literals whose type is still open. They are deliberately absent; a lowering that produced one would be a bug.

Ast below is the single type Build<A> pins for the whole grammar, so every production lowers to it whatever it is about, with a case per node kind the lowering produces.

Ast variant 

variant Ast

The one type every build in grammar_aipl.aipl returns, whatever the production is about — Build<A> pins a single A for a whole grammar, so a grammar describing a language rather than one expression type carries the seam here. Each case is a node kind the lowering produces.

Two cases are not node kinds but the intermediate a production hands its parent. Tys is the list a production whose whole content is a comma-separated run of types lowers to, and the case it lands in is what tells ty's alternatives apart — (A, B) and A reach ty as different Ast cases, so nothing has to count tokens to know which matched. Payload is a constructor pattern's slot list — each slot a pattern — and whether it was written .., which is what Pat's Ctor/Nested need and no node of its own.
