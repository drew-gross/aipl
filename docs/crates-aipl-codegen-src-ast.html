Expr struct 

struct Expr

aipl_syntax::ast::Expr — a kind, the span it was written at, and (for a block) where its *value* is.

The span is this node's *token* span, which is a superset of gazelle's: gazelle's are kept for diagnostics rather than as a record of extent, so a bracketed form's stops before its closing bracket and a unary leaves its own operator out. aipl_spans_contain_gazelles is where that is stated and checked; 5e in PARSER_LIBRARY.md is where it is argued.

value_span is a block's tail position: fn f() -> str { let a = 1; a } returns the a, but the body's span starts at the let, so a return-type error would underline the binding. It is recorded while the block is being built, where the tail is in hand, rather than re-walked at every diagnostic.

Rust spells it Option<Box<Span>>; here it is a plain Span with the *empty* one meaning "none", which is the convention already in force for a location that does not exist (see join_spans). A struct field cannot be an optional struct anyway — see the constraint list in PARSER_LIBRARY.md — and the two spellings mean the same thing, since a recorded value span is never empty: the repair that fills it in runs first.

The ty field Expr carries in Rust is absent — nothing the parser sets it.

ExprKind variant 

variant ExprKind

aipl_syntax::ast::ExprKind, all 32 cases.

Several surface forms are gone by the time they get here, because the AST is where the language stops having them: an operator is an ECall on its spelling, a range is an EConstruct of the builtin Span, a template is a chain of concat calls, and a block is a right-nested ESeq. That is the same set of desugarings gazelle's build actions do, in the same places.

ECall's method_style is the one bit that says which spelling was written: recv.f(a) is stored as the free call f(recv, a) with the flag set, so the receiver is args[0] either way.

Pat variant 

variant Pat

The one type every build in grammar_aipl.aipl returns, whatever the production is about — Build<A> pins a single A for a whole grammar, so a grammar describing a language rather than one expression type carries the seam here. Each case is a node kind the lowering produces; Ignored is what a production with no lowering yet returns.

Two cases are not node kinds but the intermediate a production hands its parent. ATys is the *list* a production whose whole content is a comma-separated run of types lowers to, and the case it lands in is what tells ty's alternatives apart — (A, B) and A reach ty as different Ast cases, so nothing has to count tokens to know which matched. APayload is a constructor pattern's slot list and whether it was written .., which is the pair Pat's PatCtor needs and no node of its own. aipl_syntax::ast::Pattern. Its Ctor case is a struct variant there and a named payload here, which is as close as the two declarations get: the slot names are the same three, in the same order.

PatArray — the destructuring [a, b] => .. arm — holds a list of *expressions*, which is why nothing under the pattern production produces one: it hangs off match_arm, where the elements are an ordinary args list.

show_pat fn 

pub fn show_pat(self: Pat) -> str

A pattern as a one-line dump, in the spelling that produced it: Ctor(a, b), Ctor(..), a bare name, _. The two literal forms are tagged, because their whole point is that they are values rather than names and "1" against 1 would otherwise read the same.

pat_bindings fn 

pub fn pat_bindings(self: Pat) -> str[]

The names a pattern binds, in order — Pattern::bindings in Rust. It is what an arm's alternatives must agree on, so that a shared body means the same thing whichever alternative matched.

An array pattern binds its EIdent elements and nothing else: a literal element is a value to match, not a name to bind.

pat_label fn 

pub fn pat_label(self: Pat) -> str

How a pattern is named in the "alternatives must bind the same names" diagnostic: the constructor for a constructor pattern, and a description for the literal forms, which bind nothing and so only ever appear on the side that binds nothing.

Suffix variant 

variant Suffix

One postfix step, before it has a receiver to apply to. postfix is an atom followed by a run of these, and a suffix on its own is not an expression — which is why it needs a shape of its own rather than an Expr.

A tuple index is a SufField: p.0 is the field named _0, which is how the AST spells it and why nothing downstream has to know tuples have a second syntax for their fields.

Stmt variant 

variant Stmt

One keyword statement, after its own production has read it and before the rest of the block is in scope. wrap_stmt is what folds it together with that rest, and several of these fold into *several* nodes — which is why a statement cannot simply lower to an Expr the way an expression does.

It mirrors gazelle's StmtSpec, which is a parser-local type there for the same reason it is one here: the AST has no statement node, so this shape exists only between the production and the fold.
