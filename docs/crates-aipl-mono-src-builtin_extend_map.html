The AIPL implementation of the extend_map builtin. The loader names this function by the canonical name __builtin_extend_map (see aipl_syntax::aipl_builtins); the in-file name is only for this file's own tests, which read exactly like the user code that never spells it.

Internal (INTERNAL_BUILTINS): the spelling in a program is set out.extend(xs.map(f)), or ..xs.map(f) in an array literal. The folder (fold_extends) turns either into this call, so the array map would have built, and the copy of it into out, never happen. It is a mut self method, so the receiver grows in place and keeps the room a literal reserved for it.
