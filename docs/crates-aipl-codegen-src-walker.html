format_program fn 

pub fn format_program(src: str, width: u64) -> str!FmtError

Format src at width, from source text to laid-out source text: lex it, walk the tokens into a Doc, then print. This is the whole formatter as far as the Rust side is concerned — arrays cannot cross the FFI as arguments, so the token stream is produced here rather than marshalled in.

The caller still owns the surrounding steps that are not layout: splitting off trailing --- section --- blocks, stripping trailing whitespace, validating with the real parser, and the token-preservation check.

more_before fn 

fn more_before(self: W, end: str) -> bool

Is there another item to read before the closing end token?

**Use this for every "scan until a closing token" loop.** The bare form

while (w.peek_text() != "}") { .. }        // WRONG

spins forever on truncated input: past the last token peek_text() is "", which never equals "}", and bump() deliberately does not advance at the end (see its comment) — so the loop makes no progress and never exits. That is not hypothetical; it hung aipl check on a truncated import with no output and no diagnostic, which is indistinguishable from a compiler hang.

Folding the at_end check in here means a caller cannot forget it. The expect(end) that follows the loop then reports the missing token properly.

case_params fn 

fn case_params(self: W, acc0: Doc[]) -> WDocs!FmtError

The payload slots, up to (not consuming) the closing ). A slot is named when an identifier is followed by : — the same two-token look the grammar takes, and the only place a : can sit second in a type is a dict's #{K: V}, which starts with #. A named slot may carry a default, spaced like a parameter's.

k?: T is the omit-able slot (see one_param). It needs one token more of look than a plain named slot, and that is exactly the look the grammar cannot take — which is why ?: reaches the parser as a single terminal there. Here the two are still separate tokens, so the third position is what tells Circle(i64?) from Many(max?: u64 = none).

fn_body fn 

fn fn_body(self: W) -> WDoc!FmtError

A function body: an ordinary statement block, or the *struct-literal shorthand* { field: value, .. }, which names no type because the declared return type supplies it. The shorthand is laid out like the struct literal it stands for — flat while it fits — not like a block, which always breaks.

{ x } stays a block returning x, so the shorthand is recognized by the token *after* the first one: neither IDENT : nor IDENT , can begin a statement, and no other body shape puts : or , in that position (a tuple or array literal leads with (/[, a call's comma sits past its (). That is the grammar's own rule, so testing the following token alone keeps the two parsers in step — testing the field name's *kind* would not, since a field may be named str, which the formatter classifies as a builtin type rather than an identifier.

construct_body fn 

fn construct_body(self: W) -> WDoc!FmtError

The shorthand body's field list, entered with the { already consumed. Mirrors struct_atom without the leading type name.

One wrinkle the ordinary struct literal doesn't have: in { id, } — a single *shorthand* field — the comma is **syntax, not style**. Drop it and { id } reads back as a block whose value is id, so formatting would change what the source means. comma_list_docs writes a trailing comma only when the list breaks (IfBroken), which is not enough here, so that comma is written into the item itself and the style's own one switched off. Every other shape already carries a comma or a colon between the braces and formats as usual.

hugs_sole_arg fn 

fn hugs_sole_arg(self: W) -> bool

Whether the call whose ( was just consumed takes exactly one argument that *is* a bracketed construct — a nested call, an array, a struct literal, or a set/dict literal — filling the parens end to end. Such a call is *hugged*: the argument's own brackets carry the break, so the nesting costs one indent level instead of one per layer. Pure lookahead over the token stream, no parse state.

walker_of fn 

fn walker_of(src: str) -> W!FmtError

A walker over src, tokenized by the real lexer — the same three lines format_program runs, so a unit assertion and the formatter proper see one token stream and cannot drift apart.

There was a stand-in here once: a tokenizer that split on single spaces and called every token an Ident, so a test could write "i64 [ ] ?" and mean five tokens without computing byte offsets. It diverged in both of the ways a stand-in can. It produced no kinds, so every walker branch on FmtKind — doc comments, string atoms, the three template positions — was unreachable from a unit test; and it accepted inputs the real lexer reads differently, which is how # { str : i64 } sat here as a set type when # in fact opens a doc comment. Avoiding that is worth the ? on every call below.
