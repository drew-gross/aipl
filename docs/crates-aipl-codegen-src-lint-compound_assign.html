The compound_assign lint: set x = x + e; — an accumulate written the long way; set x += e; is the form for it, and likewise -=, *=, /=.

For the commutative operators either operand order counts (x * k and k * x both scale x), but - and / are flagged only with the receiver on the left: set x = k - x; is not set x -= k;, and rewriting it that way would silently change the program.

The target may be a name or a field path off one (set p.n = p.n + 1; is set p.n += 1;): every set form takes either, and a path's text spells it, so the advice can quote it as written.

step_by_one has the more specific advice for set x = x ± 1; — set x++; / set x--; — wherever it has advice for the operator, so this lint leaves that shape to it rather than offering a second rewrite of the same line. Where it has none (no step flavor matches this file's operator), ±= 1 is the only advice left and this lint gives it.

Only the operators whose compound spelling provably means the same thing are advised — see paired: the compound spelling has to be the flavor of the file's operator, and one the file already binds to something else is not offered. The advice names the import to add when the file lacks it, since no compound operator has a bare form.

The hit points at the set statement.
