AIPL's TextMate grammar as .tmLanguage.json text — what editors/vscode/syntaxes/aipl.tmLanguage.json holds. Derived from aipl_rules() plus the four patterns a lexer cannot describe; see the file header.

escape_scope fn 

fn escape_scope() -> str

What an escape sequence inside a string, char or template literal is painted. One scope for all of them, since a \n means the same thing wherever it is.

ident_regex fn 

fn ident_regex() -> str

The identifier regex, built from the very classes the identifier *rule* is built from (lex_aipl.aipl), so fn NAME accepts exactly the names AIPL accepts. matcher_regex answers none only for the delimiter-scanning matchers, which a CharRun is not.

builtin_types fn 

fn builtin_types() -> str[]

The builtin type names. Lexically these are plain identifiers — the AIPL lexer emits Name for them and classify_lexed (crates/aipl-parser/src/lib.rs) is what separates them out — so there is no rule to derive this from, and this list has to stay in step with that one by hand.

effect_pat fn 

fn effect_pat() -> Pat

An effect declaration — !prints in a signature. The effect names are spelled out rather than matched as any !ident, which would mis-scope the unary ! in !true / !ready; they must stay in step with KNOWN_EFFECTS.

section_tail fn 

fn section_tail() -> Pat

A test-case file's --- name --- markers and everything after the first one. The tail is expected output, not AIPL, so it is scoped as plain content and only the markers themselves are painted — as comments, which is the closest thing a theme has to "not code". \z never matches inside the text, so the region runs to end of file.
