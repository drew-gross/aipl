LintHit struct 

struct LintHit

A hit whose message names builtins the way the file that was linted spells them. A lint cannot say how: it reads one function, and the spelling is in the import list, so it reports the message in parts — each stretch of text followed by the builtin its rewrite uses, then a closing stretch — and the framework writes each in the way the file can take (see spelling.aipl), adding the import the file lacks.

The span is where the hit points. A lint that says nothing about it leaves it empty (an empty span is no location), and the framework that ran the lint over a node points the hit at the whole node (run_lints), or over a function at the function's name ([unfilled_hits]).

spans_its_text fn 

pub fn spans_its_text(self: Expr) -> bool

Whether self's span covers exactly the text that spells it, so the source can be spliced back into advice. Only a name and a field path off one qualify: their spans run from the first character to the last. Most other forms do not — a call's span stops before its closing paren, so f(x) splices back as f(x, which doesn't parse — and the ones that might are left out rather than each having to be re-checked whenever a span moves.

functions fn 

pub fn functions(self: Program) -> Function[]

Lints come in two kinds. A program lint is a function of the whole Program (unused_imports, which compares the imports with every name the file mentions). A function lint is a function of one Function, and [hits] and its variants run it over the program's [functions], so no function lint decides for itself which bodies to look at. A function lint that needs to know the file's imports takes its items beside the function.

The program is read after hoisting, so every body that is code to check is a function: each function, the .test and .benchmark blocks as the functions they became, and the helpers declared in a block.

Every function of the program, in the order it is written.

LintRun variant 

variant LintRun

A lint of one function, by what it reads: the function (once), or each node of one kind in its body. A lint of the kind reads the kind's payload; one that needs the node itself (its source, or its span) is the Node case. What each says is a list of hits, which a lint that finds at most one writes as [..hit].

  • OfCall((Call) -> LintHit[])
  • OfMatch((Match) -> LintHit[])
  • OfMatchIn((Match, Function) -> LintHit[])
  • OfMatchNode((Expr) -> LintHit[])
