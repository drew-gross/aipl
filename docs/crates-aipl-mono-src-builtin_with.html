The AIPL implementation of the with builtin. Monomorphization registers this under the canonical name __builtin_with (see AIPL_BUILTIN_SOURCES in lib.rs), so a user's xs.with(i, v) resolves through the ordinary generic machinery.

Arrays have no element assignment, because a write to an index that is not there has nowhere to go. This is the total version of it: the answer is a new array, or none when there was no such slot to write.

No lint steers a hand-written [..xs[..i], v, ..xs[i + 1..]] here: the shape is rare, and spelling it out is not wrong in the way an ad-hoc loop is — it also does not say what happens past the end, which is the part with adds.

with fn 

pub fn with<T: any>(self: T[], index: u64, value: T) -> T[]?

A copy of self with the element at index replaced by value, or none when index is past the end — there is no element to replace, and self[index] is none there too. The receiver is unchanged. Callable as a method: xs.with(i, v).

To update a variable, match on it: set xs = xs.with(i, v).value_or(xs) keeps the old array when the write missed, which is what writing nowhere means. value_or and map are the siblings for working with the optional.
