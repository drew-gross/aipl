The two rewrites that turn a function's .test and .performance attributes into ordinary top-level functions, so that everything after the parse — the loader's rewrites included, which is how they recognize test code — sees only functions.

  • A .performance({ .. }) attribute becomes __performance$<f>: private, no

parameters, a unit body, and the block as its .test body (so aipl check runs it, assert works in it, and an imported file's is dropped, all by the machinery .test already has). It sits right after f and the helpers f's own .test block declared.

  • A function declared inside a .test block moves out to the top level under

test_helper_name, reachable only from where it was declared: its uses in the test body and in the block's other helpers (a helper may call itself and its siblings) are renamed with it, and nothing else in the file can spell the hoisted name. The helpers of one test land right after the function that carries it, in declaration order.

Renaming is by name, not by scope: a let in the test body that shadows a helper's name is not tracked, the same way a call's name resolves in the loader.
