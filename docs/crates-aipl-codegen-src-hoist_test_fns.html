The rewrites that turn a function's .test and .benchmark attributes into ordinary top-level functions, so that everything after the parse — the loader's rewrites included, which is how they recognize test code — sees only functions.

  • A .test({ .. }) block becomes __test$<f>: no parameters, the block as its

body, declaring no effect (so aipl check runs it, assert works in it, and a test shims whatever it uses). It sits right after f.

  • A .benchmark({ .. }) attribute becomes __benchmark$<f>: no parameters, a

unit body — the block itself is __test$__benchmark$<f>, which declares measure and nothing else. They sit right after f and the helpers f's own .test block declared.

  • A function declared inside a .test block moves out to the top level under

test_helper_name, reachable only from where it was declared: its uses in the test body and in the block's other helpers (a helper may call itself and its siblings) are renamed with it, and nothing else in the file can spell the hoisted name. The helpers of one test land right after the function that carries it, in declaration order.

  • A top-level test({ .. }) is carried by a function that exists only for it; the block

becomes __test$<carrier> and the carrier goes.

The functions this makes are the ones given the Test and Benchmark visibilities: a block's function is Test, or Benchmark when it is a .benchmark block, and so is the function a .benchmark hangs from.

Renaming is by name, not by scope: a let in the test body that shadows a helper's name is not tracked, the same way a call's name resolves in the loader.
