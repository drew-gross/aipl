The parser's trailing-whitespace locator: the compiler calls this through the FFI (see install_parser_hooks) from reject_trailing_whitespace on every parse, and aipl check exercises it via the .test block below. It returns a Span? — an optional builtin Span returned over the FFI — locating the first offending run, or none when there is none; aipl_str_iter_next walks src byte-by-byte, so the offsets are byte offsets, matching the parser's error rendering.

find_trailing_whitespace fn 

pub fn find_trailing_whitespace(src: str) -> Span?

The byte Span of the first line's trailing space/tab run in src as some(span), or none if no line has trailing whitespace. A single CR before a LF is part of a CRLF line ending, not content. The locator for the parser's trailing-whitespace check.

fn line_end_span(prev: char, prev2: char, boundary: u64, ws_start: u64, line_start: u64) -> Span?

The span of a line's trailing space/tab run, given the bytes around its ending, or none if the line has none. A single \r right before the boundary is part of a CRLF (or lone-CR) ending, so the last content byte is the one before it.

  • prev: char

    The byte before the line ending.

  • prev2: char

    The byte before that.

  • boundary: u64

    The index of the line-ending \n (or the input length, at EOF).

  • ws_start: u64

    Where the current run of spaces and tabs began.

  • line_start: u64

    The line's first byte.
