The map_constant_repeat lint:

xs.map(|x| c)

— where c is the same value for every element: a function that ignores its argument is a way to write "this many copies of c" that builds the copies one at a time and spells the count as a walk over xs. [c].repeat(xs.len()) says it directly — and builds c once, then copies it into an exactly-sized result.

Only a body that is constant qualifies: literals, names read as they are, and constructions or literals of those. Anything that calls a function does not, because repeat evaluates its element once where map evaluated the body per element, and a call may differ between evaluations (or have an effect). A body that mentions its own parameter is not ignoring it. Names are allowed because reading a binding gives the same value each time.

What the lint cannot see is the receiver's type: it runs before checking, and opt.map(|_| c) is the optional's map, for which .len() and repeat are no answer. The advice is worded for a sequence for that reason, and a receiver that is a range is skipped outright, being syntactically what it is. The cost of the remaining case is one #[allow] on a legitimate optional map.

The hit points at the lambda, a short span that begins on the line the #[allow] would be written on.
