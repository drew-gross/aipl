The names the parser gives functions it synthesizes from a declaration's attributes, and the inverse: what a function's name says it is.

A .test({ .. }) block on f becomes the function __test$f; a function declared inside that block is hoisted to __test$f$helper; a .performance({ .. }) block on f becomes __performance$f, whose own .test body is the block. A $ cannot appear in a source name, so no program can spell any of them, and a $ past the prefix is the mark of something synthesized from a body rather than the body itself — a lambda lifted out of a test body is __test$f$lambda0, and its ? acts on the lambda's own return type.

Rust asks the questions of this file through the FFI (fn_role, test_fn_name, performance_fn_name); test_helper_name is only asked by the pass that hoists helpers, which is AIPL too.

FnRole variant 

variant FnRole

What a function's name says it is. A source name is Plain.

  • TestBody: exactly a .test body (__test$f, or __test$__performance$f

for a .performance block).

  • TestHelper(helper): a function hoisted out of a .test block, with the

name it was declared with.

  • Performance(source): the function standing for source's .performance

block.
