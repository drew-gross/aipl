The slice_whole lint: x[0..], x[..x.len()] and x[0..x.len()] — a slice whose range covers the receiver end to end, which is what x already is. The slice is not free: an array slice allocates a fresh block and copies every element, so this is a redundant copy as well as a redundant spelling. Dropping it is safe because arrays have value semantics — mutating an aliased binding copies first, so y = x cannot be surprised by a later set x[..].

This is the whole-range corner of the three slice lints, and it takes priority over both: slice_to_len would advise x[0..] and slice_from_zero x[..x.len()], each of which is still this shape and would need a second round trip. Both bow out when this one applies, so a full-range slice produces exactly one hit whichever way it was written.

A start of 0 counts however it was written. The hit points at a bound rather than the whole slice, because #[allow] is line-scoped and a receiver may span lines while a bound sits inside the brackets: the written 0, or when the start was left out (x[..x.len()]), the end bound, which must be there in that form.
