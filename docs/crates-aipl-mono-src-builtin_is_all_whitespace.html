The AIPL implementation of the is_all_whitespace builtin. Monomorphization registers this function under the canonical name __builtin_is_all_whitespace (see AIPL_BUILTIN_SOURCES in lib.rs), so a user's s.is_all_whitespace() resolves through the ordinary machinery — the in-file name is only for this file's own tests, which read exactly like user code.

It was a native runtime function (aipl_str_is_all_whitespace) and is now AIPL, which is the direction the whole compiler is headed. Two things made the port honest rather than approximate:

  • a str receiver iterates its chars, so all is the whole implementation;
  • is_whitespace — not is_space — is the predicate. They differ, and the difference is the reason is_whitespace exists: is_space accepts space, tab, newline and carriage return, while ASCII whitespace also includes vertical tab and form feed. The native version accepted all six, so narrowing to four would have been a silent behaviour change. AIPL has no numeric escape, so those two bytes cannot be written in source at all — which is why the predicate covering them is a compiler intrinsic.

Empty is all-whitespace, by all's vacuous truth — the same answer the native version gave, and consistent with "".trim() == "".

pub fn is_all_whitespace(self: str) -> bool

True when every char of self is ASCII whitespace — space, tab, newline, carriage return, vertical tab or form feed — and true for the empty string. Callable as a method: s.is_all_whitespace().

See is_whitespace for the per-char predicate, and is_space for the narrower four-character one.
