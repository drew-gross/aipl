The token kinds. One terminal class carrying its text, and one bare kind for the parentheses — the grammar matches those by Lit, so their kind never has to be distinguished.

sexp_grammar fn 

pub fn sexp_grammar() -> Grammar<SexpKind, Sexp>

The S-expression grammar: list -> "(" item* ")" and item -> Atom | list, with item as the start rule so a bare atom is as much a program as a list is.

item is labelled and list is transparent, so a failure inside a list reports as "an s-expression" rather than as the grammar's internals — the collapse expect_as exists for.

sexp_cst fn 

pub fn sexp_cst(src: str) -> Cst!ParseError

The lossless concrete tree for src — every byte of it under exactly one leaf, comments and whitespace included. Use this when the tree is the point; parse_sexp when only the Sexp is.

parse_sexp fn 

pub fn parse_sexp(src: str) -> Sexp!ParseError

The Sexp src denotes: lex, parse to a concrete tree, lower it through the grammar's build functions.

Fails with a ParseError carrying the span of the offending token, from either half of the front end — a lex error is reported in the same shape.

format_sexp fn 

pub fn format_sexp(src: str, width: u64) -> str!ParseError

src reformatted: parse it to the concrete tree, then lay that out at width.

Nothing here knows what an S-expression looks like. The layout is the two annotations on the grammar above, and everything else — where a list breaks, what happens to the author's blank lines, where a comment lands — is format.aipl reading them. That is the whole point of the exercise: a second hand-written walker over the same syntax is what this replaces.

sexp_rules fn 

fn sexp_rules() -> TokenRule<SexpKind>[]

Whitespace and ; comments are recorded as **trivia** rather than skipped, so the concrete tree covers every byte of the source and reconstructs it exactly (asserted below). An atom is a run of the usual Lisp symbol characters, which includes digits — this grammar has no number type, so 12 is just an atom.

lower_list fn 

fn lower_list(src: str, node: Cst, kids: Sexp[]) -> Sexp!ParseError

A list node's children are exactly its interior items — the parentheses are leaves, and leaves have no lowered value — so the list *is* its kids.

lower_item fn 

fn lower_item(src: str, node: Cst, kids: Sexp[]) -> Sexp!ParseError

An item is one of its two alternatives, told apart by whether it got an interior child: the list branch lowered one, and the Atom branch matched a bare token, whose spelling is the node's own text with trivia dropped.

sexp_space fn 

fn sexp_space(l: str, r: str) -> bool

S-expressions have no spacing rule to speak of: every separation in the language is a list separating its elements, which the Wrap layout does. The rule still has to exist — format.aipl asks every language the same question — and answering "never" is the honest answer here.
