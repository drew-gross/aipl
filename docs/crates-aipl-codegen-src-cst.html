Cst variant 

variant Cst

An interior node is Tree(prod, kids); a Group is the bracket pair a bracketed repetition matched, holding its opening kids, the kids between the and its closing kids as three runs.

A group is *transparent*: it is not a production, it lowers to nothing of its own, and nodes and own_tokens splice straight through it — so converting a Then([Lit("("), x, Lit(")")]) into a nested_in leaves every build function reading exactly the children it read before. The only pass that sees a group is the formatter, which is the pass that needs to know where the brackets are.

leaves fn 

pub fn leaves(self: Cst) -> Span[]

Every leaf span under self, in source order — token leaves and trivia alike. The whole losslessness property is stated in terms of this list: the spans are contiguous and cover the parsed source, so text is just "slice each one and join".

text fn 

pub fn text(self: Cst, src: str) -> str

The source text self covers, reconstructed from its leaf spans. For a whole parse this equals the input exactly; that identity is the cheapest regression test there is for the driver's trivia handling, so the .test blocks assert it directly.

token_leaves fn 

pub fn token_leaves(self: Cst) -> Span[]

Every *token* leaf span under self, in source order — leaves with the trivia dropped. The two are the lossless/meaningful pair: leaves keeps the comments and whitespace because reconstructing the source needs them, and this one drops them because a lowering function reading a token's spelling does not want the blank line in front of it.

token_span fn 

pub fn token_span(self: Cst) -> Span?

The span self's own *tokens* cover: its first token leaf's start through its last token leaf's end, or none when it holds no token at all (an interior node for a production that matched empty input).

span reaches back over the trivia in front of the first token, because trivia attaches to the token that follows it and losslessness needs it counted somewhere. That makes span the wrong thing to compare against another parser's spans, which are token-tight — every comparison is off by the leading whitespace. This is the tight one.

Found by descending to the leftmost and rightmost token rather than by collecting every token under self and taking the ends: token_leaves walks the whole subtree, and asking it at every node in a tree is quadratic in the tree. These two descend one edge at a time and stop at the first token.

token_text fn 

pub fn token_text(self: Cst, src: str) -> str

The text of the tokens under self, trivia dropped and nothing inserted between them — what a production's build reads a matched token's spelling from. Written for the single-token node that is the usual case; over a wider node the tokens run together (( a b ) reads back as (ab)), which is why text and not this one is what reconstructs source.

extent fn 

pub fn extent(self: Cst) -> Span

The extent self covers: its first leaf's start through its last leaf's end. A node with no leaves at all — an interior node for a production that matched empty input, which Maybe and a zero-minimum Many can both produce — has no extent, and reports the empty 0..0.

Named extent rather than span because span is what a lowering asks its Node for, and AIPL has no overloading. This is the tree's own answer, which the Parts one delegates to; trivia at either edge is counted in, so token_span is what lines up with another parser's spans.

By descent, like token_span, and for the same reason: this is asked at every node a lowering visits, and collecting every leaf beneath each of them is quadratic in the tree. A block is a right-recursive chain one node deep per statement, so on the largest compiler sources that was most of the lowering's time.

Parts struct 

struct Parts

What a Mk/TryMk lowering is handed: the node that matched, and the two lists every lowering reads off it — its interior children and its own token spans — already computed.

They are precomputed because they used to be three separate walks of the same kids. lower_node asked for the children, then the build asked for the own tokens, and more than half of them asked for the own *texts* as well; each ask rebuilt the flattened kid list from scratch, and rebuilt it by allocating a one-element array per kid and joining them. One walk fills both lists, and measured against the old shape on a nine-kid node it is a little under four times faster.

cst is the node itself, for the accessors that have to descend — span, tok_span, text. Those stay lazy: each is asked at most once per lowering, so precomputing them would only move the same work earlier, and the ones that walk the whole subtree would then be paid by the lowerings that never ask.

parts fn 

pub fn parts(self: Cst) -> Parts

self as the Parts a lowering is handed: one walk of its direct kids, splitting them into the interior children and the token leaves.

The two lists are the pair a production's build is written against, and between them they are everything the node matched *directly*:

- children is one entry per Named reference the rule matched, in the order it matched them — the order and length are part of the contract between a grammar and its lowering functions. Leaves are dropped because the lowering pass has nothing to hand build for one: a leaf has no lowered value, and its text is reachable from the node's own span. - tokens is the node's direct token leaves — where a lowering reads an operator or a keyword. A Climb node's two operands arrive as interior children and the operator between them is a direct leaf, so tokens is the operator and nothing else, where token_text would hand back the whole expression's tokens run together.

Trivia is dropped from both. A Group is spliced in place rather than recorded — that splice is the one thing making a group transparent, so a production that gained a bracket pair hands its build the children it had before — and a group nested directly inside another flattens with it.

Slot variant 

variant Slot

One position of a production's rule, as the match filled it: the token a Lit/Term sub-rule consumed, or the index of the child a Named sub-rule produced — an index into children, and so into the lowered values a build is handed alongside.

This is the rule read back as a positional list, which is what lets a build *match* the shape it matched rather than reconstruct it. field_decl's two alternatives are five sub-rules and three, so an arm binding five slots is the one with a default — where counting interior children or searching the token list for an = is the same question asked sideways.

A slot *names* a position rather than carrying its contents, which is the whole reason this type is not generic. Holding the lowered value instead — Sub(A), with A the caller's AST — makes every slot a composite carrying a large recursive variant, and the refcount glue for it is generated at every site that touches one: measured, that made the accessor that reads a slot's child ten times the size of the kids-indexing version it replaced, and grew each converted production fivefold. An index costs a word and no glue.

A slot is one sub-rule only where that sub-rule matches exactly one kid, which is every Lit, Term and Named. A Maybe or a Many contributes as many slots as it matched kids, so a rule holding one does not line up position for position and its build still reads children and tokens.

slots fn 

pub fn slots(self: Parts) -> Slot[]

self's direct kids in source order — the positional view a build matches on in place of deducing its shape.

Asked for by the builds that want it, off the Parts a Mk/TryMk build already holds, so wanting positions needs no Build case of its own. It is not what parts returns because the interleaving is the one thing parts throws away (it splits the kids two ways, losing the order between them), and recovering it costs a second walk of the direct kids — which most productions have no use for.

The span self's *tokens* cover, falling back to its full extent when it matched no token at all. The span a lowering hands to the AST node it builds, and the one it blames in an error: token-tight, so it lines up with what another parser would report rather than reaching back over leading trivia.

This node's own tokens as their text, one string per token. A str is a view into src, so this costs no more than the spans do, and a lowering that asks "which token is second?" gets a string to compare rather than a span to look up.

The source text of self's direct token leaves, run together with nothing between them — the operator of a binary node, the keyword that opened a form.
