The AIPL implementation of the error_of builtin. The loader names this function by the canonical name __builtin_error_of (see aipl_syntax::aipl_builtins); the parser writes result! as a call to it, so parse(src)! is parse(src).error_of().

It is the result-world way to ask what went wrong, as is_err_and is the way to ask whether a given thing did. It exists mainly for tests that assert on a failure: == doesn't span the two sides of a result, so without it every such assertion needs a hand-written match helper per type. parse(src)! == some("unexpected end") reads as it means.
