The len_gt_zero lint: 0 < x.len() / x.len() > 0, and !x.is_empty() — non-emptiness asked the long way. x.is_nonempty() asks the question directly: it says what the test means rather than leaving the reader to recognize the idiom (or to hold a negation), and it is the one spelling that reads the same for every receiver len takes.

Only these shapes qualify. 0 > x.len() and x.len() < 0 are something else entirely (both are always false on an unsigned length), and the != 0 spellings are left alone: this lint's job is the idioms people actually reach for, not every expression that happens to mention a length and a zero. The negated predicate is the mirror of is_empty_longhand's !x.is_nonempty(); between the two, a predicate is never negated to ask the other one.

What a call is to is what the file's imports make of its name, so the operators and len are found however the file spells them, and a file that aliases < to a function of its own has a 0 < x.len() that is not a length test at all. The same goes for len: a file's own len is a different function answering a different question, and is_nonempty does not apply to what it takes.

The receiver is quoted only where the rewrite is a literal splice: a call's span stops before its closing paren, so splicing len(f(x))'s receiver would produce advice that does not parse.
