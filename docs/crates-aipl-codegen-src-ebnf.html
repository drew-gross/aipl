Ctx variant 

variant Ctx

Where a rule sits in its parent, which is all that decides whether it needs parentheses. Alt is a production's whole right-hand side, where nothing binds looser and even a choice renders bare; Seq is one element of a sequence, where a choice needs parentheses but a nested sequence does not (concatenation is associative, so it flattens); Item is the operand of a postfix ?/*/+, where both need them.

ebnf fn 

pub fn ebnf<K: variant, A: any>(g: Grammar<K, A>) -> str

g rendered as EBNF: one name = rule ; line per production, in grammar order, with no trailing newline.

Sequence is juxtaposition, choice is |, and repetition is the postfix ? (Maybe), * (Many with minimum 0) and + (Many with minimum 1); a higher minimum renders as {n,}. A separated Many and a Climb have no EBNF operator and are expanded — the list into its separator longhand, the climb into atom (op atom)* plus a (* precedence: ... *) note, since EBNF cannot express binding power.

Total, like cst.aipl's show: a grammar may be dumped linked or unlinked, and a reference that resolves to nothing renders as ? rather than failing.

Sym variant 

variant Sym<K: variant>

A terminal a match can begin with: a token *kind*, as Term matches it, or an exact *spelling*, as Literal does. Kept apart because the two tests are different — a kind ignores the token's text, a spelling ignores its kind — so a set holding SKind(Num) and one holding SText("1") are not the same set even where they accept the same token.

First struct 

struct First<K: variant>

What one production (or one rule) can begin with: the terminal set, and whether it can match nothing at all. nullable is not a property of the set — an empty set with nullable: true is a rule that matches only emptiness, and a non-empty set with it is one that may or may not consume — so both travel together.

first_sets fn 

pub fn first_sets<K: variant, A: any>(g: Grammar<K, A>) -> First<K>[]!ParseError

The FIRST set of every production of g, in grammar order: the terminals a match of that production can begin with, and whether it can match nothing.

g is linked here, so it may be handed over unlinked; linking is idempotent. Fails only the way link fails — an unresolved reference, or a duplicate rule name.

Computed as a fixed point, so a reference reaching back through the production it started from is fine, left recursion included: the sets only grow, and the loop stops on the round that changes nothing.

rule_first fn 

pub fn rule_first<K: variant>(r: Rule<K>, sets: First<K>[]) -> First<K>!ParseError

What an arbitrary rule can begin with, given sets — the FIRST sets of the grammar's productions, as first_sets returns them.

This is the piece a driver would prune a OneOf with: first_sets once per grammar, then this per alternative. Fails on a Named reference, which means the rule came from an unlinked grammar, and on a NamedIdx pointing past the end of sets.

Takes a *linked* rule, which is also a desugared one: a Many still carrying nested_in would report what its items begin with rather than its opening bracket. link writes the shorthand out, so anything that has been through it is safe here.

can_start fn 

pub fn can_start<K: variant>(self: First<K>, kind: Case<K>, text: str) -> bool

Whether a token of kind kind spelled text could begin a match of self — the test a driver skips an alternative on.

A nullable rule accepts anything, because it can match without consuming the token at all; otherwise the token's kind is looked for among the set's kinds and its spelling among the set's spellings. Conservative in the direction that matters: it is never false for a token that could in fact start a match, so pruning on it cannot lose a parse.
