Pat variant 

variant Pat

aipl_syntax::ast::Pattern, less its Bind case. Its Ctor case is a struct variant there and a named payload here, which is as close as the two declarations get: the slot names are the same three, in the same order.

Ctor and Nested split one source shape between them: a constructor whose slots are all plain names is the Ctor it always was, so an arm written the old way lowers as it always did, and only a constructor over real sub-patterns is Nested — nested_or_ctor makes that choice. Whether a bare name in a nested slot binds or names a case is decided on the Rust side (Pattern::normalized, the Bind case this declaration lacks), by the same rule is_binder_name states here.

  • Ctor(name: str, bindings: str[] = .., ignore_payload: bool = ..)

    A constructor whose slots are all plain binder names — some(v), Pair(a, b) — or a bare name (none, Nil), or the Ctor(..) form that matches a case and ignores what it carries. The two optional slots are both "nothing" for a bare name, which is the common construction.

    • name: str

      The case name, as written — qualified (V.A) or not.

    • bindings: str[] = ..

      One binder per payload slot, in slot order; empty for a bare name.

    • ignore_payload: bool = ..

      Whether the arm was written name(..): the case's payload is matched but nothing is bound. Never true alongside bindings.

  • Str(str)

    A string literal pattern ("lit" => ..), against a str scrutinee.

  • Char(char)

    A char literal pattern ('c' => ..), against a char scrutinee.

  • Array(Expr[])

    The destructuring [a, b] => .. arm. The elements are *expressions*, not patterns — the arm hangs off match_arm, where they are an ordinary args list.

  • Wildcard

    _ — matches anything, binds nothing.

  • Tuple(Pat[])

    (p, q) — a tuple of sub-patterns, one per element.

  • Nested(name: str, args: Pat[])

    A constructor whose slots are patterns rather than plain names — some(1), Pair(x, none). A slot that is a bare name is a nullary Ctor here; whether it binds or names a case is decided on the Rust side.

    • name: str

      The case name, as written.

    • args: Pat[]

      One sub-pattern per payload slot, in slot order.

  • Int(i64)

    An integer literal pattern (1 => ..).

is_binder_name fn 

pub fn is_binder_name(self: str) -> bool

Whether a bare name in a nested pattern slot is a binder rather than a case: everything but none and a capitalised name. The one rule that needs no type, stated once here and once in aipl_syntax::ast::is_binder_name.

nested_or_ctor fn 

pub fn nested_or_ctor(name: str, args: Pat[]) -> Pat

A constructor over sub-patterns, as the simplest Pat that spells it: the plain Ctor when every slot is a bare binder name, else Nested. A nullary sub-pattern arrives as a nullary Ctor (the parser cannot tell a binder from a case by shape alone), which is what the binder test reads.

show_pat fn 

pub fn show_pat(self: Pat) -> str

A pattern as a one-line dump, in the spelling that produced it: Ctor(a, b), Ctor(..), a bare name, _. The two literal forms are tagged, because their whole point is that they are values rather than names and "1" against 1 would otherwise read the same.

pat_bindings fn 

pub fn pat_bindings(self: Pat) -> str[]

The names a pattern binds, in order — Pattern::bindings in Rust. It is what an arm's alternatives must agree on, so that a shared body means the same thing whichever alternative matched.

An array pattern binds its Ident elements and nothing else: a literal element is a value to match, not a name to bind.

pat_label fn 

pub fn pat_label(self: Pat) -> str

How a pattern is named in the "alternatives must bind the same names" diagnostic: the constructor for a constructor pattern, and a description for the literal forms, which bind nothing and so only ever appear on the side that binds nothing.

The binder list as the same diagnostic writes it: each name quoted, or the word "nothing" when there are none.
