The slice_to_len lint: x[y..x.len()] — the end bound is the receiver's own length, which is what the open-ended x[y..] already means. Purely syntactic: the receiver and the len argument must be the same expression, so aliases or computed receivers that merely happen to be equal at runtime are not flagged.

A zero start makes this the whole receiver, which slice_whole reports, and its advice (x) is better than the x[0..] this one would give.

The hit points at the end bound.
