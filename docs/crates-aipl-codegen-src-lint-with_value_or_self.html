The with_value_or_self lint:

xs.with(i, v).value_or(xs)

— a replacement that falls back to the array it was replacing in. That is xs.try_set(i, v), which says it directly: a write past the end does nothing.

The longhand also reads xs twice, and the first read is the one that wants to be a move: with writes into an array nobody else holds, and the fallback is someone else holding it. So it can never write in place; try_set can.

Only when the fallback is the same place as the receiver — a binding, or a field path off one. A different array (xs.with(i, v).value_or(ys)), or an empty one (.value_or([]), for an index known to be in range), says something else and is left alone. A function of the file's own named with or value_or is not the one this lint knows the meaning of, so both have to be imported from builtins; try_set only decides whether the advice names an import too.

The hit points at the fallback.
