The formatter's pre-pass: trailing spaces and tabs come off every line before layout, so every span the walker copies verbatim refers to the cleaned text. The language rejects trailing whitespace, so removing it can't change the meaning of a program the parser would accept.

pub fn clean_trailing_whitespace(src: str) -> str

src with the trailing space/tab run removed from every line. Line endings are preserved exactly — splitting and rejoining on \\n puts back what was there, including a trailing newline or its absence.

Only spaces and tabs count as trailing whitespace, so a \\r before the \\n of a CRLF ending is content: it stops the trim, and whitespace before it survives. The formatter's input has already been through the parser's trailing-whitespace check, which treats CRLF the same way.
