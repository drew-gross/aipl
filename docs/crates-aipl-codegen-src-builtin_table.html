crates/aipl-codegen/src/builtin_table.aipl

Every importable builtin: which callee it is, where its signature and documentation come from, what else its source exports, and the library an import takes it from.

A builtin is one of three kinds. Written is an ordinary AIPL file in aipl-mono/src/, whose pub fn and # .. block are its signature and documentation. Declared is expanded or generated by the compiler and typed by a declaration named __builtin_<name>. Described is typed by a rule in the checker with nothing to read, so its signature and prose are written here.

The table is in the order the arms of the Rust Callee list the importable builtins. Rust reads it through the embedding FFI; the lints read it as Callee.

Public

Callee variant 

variant Callee

What a call is to. The importable builtins have a case each, named as the Rust Callee arm is; Some, Ok, Err and Assert are the names the language reserves; a call to a name the file does not import from a builtins library is User (is_method says whether the file's own function it names takes self first, so recv.f(..) can call it), or Local where a local holding a function hides the name. Unresolved is what the parser writes, before resolve_callees decides.

is_method_callable fn 

pub fn is_method_callable(self: Callee) -> bool

Whether a call to self can be written with the first argument as its receiver: a function of the file's own that takes self first, or a builtin. A local that holds a function, a reserved name and an unresolved call cannot.

BuiltinEntry struct 

struct BuiltinEntry

lint_table fn 

pub fn lint_table() -> BuiltinEntry[]

The table the lints read: the importable builtins, and the operator builtins that Rust resolves to another's callee. Each is a builtin the file imports under its operator (wrapping_increment as ++), so a lint can say which one a call is, and what to advise, without the written name.
