JsonTok variant 

variant JsonTok

The token kinds: three terminal classes that carry meaning, and one bare kind for the punctuation the grammar matches by Lit.

Str keeps its delimiter-stripped contents (the lexer's Delimited computes them), but the concrete tree holds *spans*, not values — so lowering reads the quoted source text back out and strips it itself. The payload is what makes a string token tell itself apart from a number, which is all Term needs.

pub fn json_grammar() -> Grammar<JsonTok, Json>

The JSON grammar, with value as the start rule.

Only value carries an expect_as, so a failure anywhere inside reports as "a JSON value" rather than as the six alternatives it is made of — the collapse that keeps a PEG's error messages readable.

parse_json fn 

pub fn parse_json(src: str) -> Json!ParseError

The Json src denotes: lex, parse to a concrete tree, lower it through the grammar's build functions.

Numbers arrive as their source spelling (JNumber("1e9")), since JSON's number syntax is wider than any one AIPL type — parsing one is the consumer's policy.

render_json fn 

pub fn render_json(self: Json) -> str

self printed back as JSON source, in one canonical compact spelling: no spaces, no trailing separators, strings escaped.

Round-trips with parse_json — parse_json(render_json(v)) == v for every v a parse produced — which is what makes the pair a usable end-to-end check of the library.

A bare JMember renders as the "key":value it is; it is only meaningful inside a JObject, which is where a parse ever puts one.

format_json fn 

pub fn format_json(src: str, width: u64) -> str!ParseError

src reformatted: parse it to the concrete tree, then lay that out at width.

The whole of JSON's layout is the eight annotations on the grammar above plus json_space below. There is no second walker over JSON's syntax, and adding a ninth production would need no more than a ninth annotation — which is the claim this stage exists to make good on.

json_rules fn 

fn json_rules() -> TokenRule<JsonTok>[]

Whitespace is recorded as **trivia** rather than skipped, so the concrete tree covers every byte of the source and reconstructs it exactly. JSON has no comments, so trivia is whitespace and nothing else.

Rule order carries two decisions. Float sits ahead of Int because a bare digit run doesn't match Float and 1.5 would otherwise lex as 1 then a stray .. And Exact("-") sits ahead of both, which makes every - its own token and Int unsigned — so the sign is the *grammar's* business (Maybe(Lit("-")) in number), one place, rather than split between a sign the lexer swallowed and one it didn't.

json_space fn 

fn json_space(l: str, r: str) -> bool

JSON's whole spacing rule: a space after the : of a member, and nowhere else. Everything else that looks like spacing — between members, inside braces — is a list breaking or not breaking, which the layouts decide.
